# 월별 참조 수정: 조건·예상값 확정

상태: 명세 확정. 구현·수정 기능 시험은 아직 하지 않음. 기존 탐지 예상값/Excel 증거 재사용.

## 고객 결과와 첫 지원 범위

등록된 합성 샘플 한 개의 Budget!N18에 대해, 주변 월별 계산과 같은 기준으로 바꾸는 수정안을 제시한다. 고객은 전후 수식·계산값·영향을 확인하고 별도로 승인한다. 원본을 보존하고 수정본 XLSX·변경내역 XLSX·재검증 HTML을 받는다. 고객의 업무상 정답을 자동 확정하지 않는다. 첫 구현은 단일 셀/단일 월별 참조 수정으로 제한하며 다른 수정과의 묶음 결합은 이번 명세 범위 밖이다.

고정 답: `=N15-N14` / `#VALUE!` → `='M10'!B16-'M10'!B15` / **-5**. 1001-1006=-5. 수정 셀 정확히1개, 해당 위치의 탐지 후보0개. 정상 원본과 동등한 `=N16-N15`는 수정 제안0개. 숨김 열 사례도 수정0개이며 지원 불가로 분리한다. 탐지0건이 전체 안전성을 뜻하지 않는다.

## 수정안 제시 조건

- 명시적인 M01~M12 머리글과 실제 월별 시트가 일대일 대응한다. 기존 MONTHLY-01 탐지 조건을 모두 만족해야 한다.
- 같은 행의 연속 수식4개 이상, 동일한 월별 뺄셈 기준3개 이상, 내부 이탈1개, 바로 양옆의 기준 일치. 한정된 머리글 후보가 유일해야 한다.
- 양옆 수식의 월 이름만 대상 월로 대응시키면 동일한 단일 후보가 되어야 한다. 월별 시트의 A1 주소는 그대로 두며, 단순 옆 셀 복사/Translator 이동으로 생성하지 않는다.
- 피연산자는 같은 대상 월 시트의 고정된 두 단일 A1 셀, 실제 값은 유한한 숫자. 정상 동등 표현은 오류로 보지 않는다.
- 파일 보존·크기·셀/수식 수·지원 문법·전체 의존 관계 검사와 실제 재계산을 통과해야 한다. 첫 샘플이 이 조건을 넘으면 중단하고 별도로 보고한다. 한도를 자동 완화하지 않는다.
- 기존 `#VALUE!` 허용은 새 프로필의 정확한 단일 대상에만 제한한다. 다른 기존 오류나 수정 후 오류는 납품 거절. 영향 범위의 새 후보/오류를 감추지 않는다.

## 거절 조건

머리글/월 시트 불명확, 기준 여러 개, 복수 이탈/끝점 이탈, 숨김·병합·Table·수동 예외, 외부/이름/구조화 참조, 함수·범위·고정 참조·혼합 월, 지원하지 않는 OOXML/계산 조합, 숫자가 아닌 피연산자, 비대상 기존 오류, 순환/깊이 초과, 만료·변조된 계획, 변경 전 원본/수식 불일치, 명시 승인 없음은 수정하지 않는다. 결제와 읽어봄은 승인으로 인정하지 않는다.

## 재사용과 새 구현의 경계

재사용 후보: 원본 스냅샷/해시, 정확한 계획 digest와 만료·소유자 확인, 승인/실행 분리, 보존 안전한 패치·세 파일 납품·재검증 구조. 재사용 가능하다는 뜻이지 새 프로필 호환 시험이 끝났다는 뜻은 아니다.

새로 필요한 부분:

1. **한정된 내부 시트 참조 계산 지원**. delivery_inputs.py는 `!`를 UNSUPPORTED_FORMULA로 거절한다. delivery_calculation.py의 참조·의존 그래프는 같은 시트를 가정한다. 문법, 시트별 의존 관계, 순환 검사를 함께 확장·검증해야 하며 `!` 차단만 제거하면 안 된다.
2. **기존 수식 교체 전용 규칙**. repair_rules/formula_restore.py는 실제 blank만 허용한다. RP02를 넓히지 않고 새 프로필에서만 before 수식/해시가 정확히 맞을 때 교체한다.
3. **정확한 대상의 기존 오류 처리**. delivery_plan.py는 기존 계산 오류를 모두 거절한다. 새 프로필의 목표 셀1개만 별도 정책으로 다루며 기존 RP01/RP02 오류 정책을 그대로 둔다.
4. 프로필 등록·계획·영향 계산·참조 기준·UI·납품/재검증 통합을 확인해야 한다. 엔진 fingerprint 변경 시 기존 Excel/runtime 기준 증거를 자동으로 PASS 재사용하지 않는다.

## 반드시 확인할 기능과 순서

다음 한 단위: 한정된 내부 월별 시트 참조의 계산·의존 관계 지원. 아직 수정 기능을 노출하지 않는다. `1001-1006=-5`, 없는 시트/외부 참조 거절, 시트 간 순환 탐지, 기존 두 프로필 정책 보존을 표적시험으로 확인한다. 구현자가 결과로 예상값을 바꾸지 못하도록 이 oracle을 고정한다.

그 다음 별도 단위: 교체 전용 프로필과 정확한 승인계획. 이후 통합 단계에서 실제 Excel 계산값·원본/비대상 보존·재검증 탐지0건·기존 두 수정 회귀를 확인한다. 마지막으로 베타 화면의 제안→전후 예시→별도 승인→세 파일 다운로드와 고정 예상값을 대조한다. 각 단위 완료 후 사용자 확인을 받고 다음 단위로 간다.

## 증거와 한계

acceptance-oracle.json과 sha256은 이번 수정 요구의 고정 기준이다. 월별 탐지의 기존 oracle, 정상 샘플 native 결과 N18=-5 및 네 입력 해시를 읽기 전용으로 대조했다. 과거 full300 truth/샘플/실행 기록은 수정하지 않았다. 새 수정 기능, PG, 상용 준비 또는 새 native 실행의 PASS로 보고하지 않는다. 명세 및 기록만 추가; 코드/배포/Git push 변경 없음.
