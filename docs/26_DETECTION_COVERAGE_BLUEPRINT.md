## M4-A.6 해석과 추가 경계

M4-A.5의 `CONDITIONAL GO`는 내부 베타 **계약 준비**를 허용하는 제품 소유자 결정이다. 현재 두 프로토타입을 공개 기능으로 바꾸거나 사용자 화면을 구현하는 승인이 아니다.

- 40개 고정 합성 case의 precision·recall·F1 1.00은 현재 정의한 합성 corpus의 결과다. 엔진과 corpus가 같은 개발 과정에서 만들어졌으므로 실제 업무 파일의 상용 정확도·업무 수식의 정답·결제 가치를 증명하지 않는다.
- 다음 독립 검토는 별도 작성한 합성 holdout부터 시작한다. 실제 비민감 파일 검토가 필요해진다면 개인정보·보관·접근 승인을 별도로 받는다. M4-A.6에는 실제 회사 파일이나 사용자 반응이 없다.
- 30,000 수식 셀에서 1.4920초의 절대 추가 시간은 선택형 내부 정밀검사의 후보 근거가 될 수 있다. 그러나 2.198×–2.545×의 상대 증가도 D-042에 따라 계속 공개·검토하며, 더 큰 파일에 일반화하지 않는다.
- 내부 베타의 현재 검증 범위는 기본 스캔 완료, `scan_truncated=false`, 수식 셀 1~30,000개다. 이 범위를 벗어나면 후보를 억지로 만들지 않고 실행 결과를 유보·생략해야 한다.

M4-B 계약과 현재 구조의 차이는 `docs/28_M4B_PRODUCT_CONTRACT.md`에 기록한다. 현재 feature flag를 켜면 M4 후보가 기본 collector에 합쳐져 risk·quote·기본 목록에 영향을 줄 수 있으므로, M4-B에는 별도 audit envelope와 기본 결과 불변성 회귀 테스트가 필요하다.

## 제품 원칙

1. **조용히 틀릴 수 있는 구조 위험을 우선한다.** Excel이 명시적으로 `#REF!`를 보이는 경우보다, 수식 영역의 상수 덮어쓰기·수식 누락·참조 또는 범위 이탈처럼 파일은 정상으로 보이지만 결과가 달라질 수 있는 신호를 우선 검토한다.
2. **후보는 오류 확정이 아니다.** 정적 구조 비교만으로 업무적 정답, 계산 결과, 손실, 안전한 수정 수식을 단정하지 않는다.
3. **근거와 다음 행동이 없는 탐지는 공개하지 않는다.** 각 공개 후보는 발견 사실, 가능한 영향, 정상일 수 있는 조건, 이번 검사 한계, Excel에서의 확인 방법을 제공해야 한다.
4. **수정 가능성은 별도의 안전 판정이다.** 탐지, 정밀 검증, 사용자 승인, 별도 수정본 생성, 재검증은 서로 다른 단계다. 이 문서는 Approved Repair를 구현하거나 승인하지 않는다.
5. **민감 정보는 최소화한다.** 로그·평가 산출물에 원본 파일명, 셀 값, 원문 수식, 시트명, 좌표, finding key를 남기지 않는다. 사용자 응답의 위치 정보도 해당 기능의 개인정보·보관 검토를 통과한 경우에만 제공한다.

## 규칙 코드와 evidence subtype

`rule_code`는 사용자에게 제공할 수 있는 **독립적인 탐지 계약**이다. `evidence subtype`은 그 규칙이 감지한 패턴 차이의 설명이며, 독립 규칙 수나 우선순위에 중복 집계하지 않는다.

현재 예시는 다음과 같다.

- `FORMULA_PATTERN_OUTLIER` 한 규칙의 subtype: `FUNCTION_PATTERN_DRIFT`, `REFERENCE_SHEET_DRIFT`, `RELATIVE_REFERENCE_DRIFT`, `ABSOLUTE_REFERENCE_DRIFT`, `RANGE_BOUNDARY_DRIFT`, `GENERIC_PATTERN_DRIFT`
- `FORMULA_PATTERN_GAP` 한 규칙의 subtype: `CONSTANT_OVERRIDE_CANDIDATE`, `BLANK_GAP_CANDIDATE`

`GENERIC_PATTERN_DRIFT`는 설명 근거가 충분하지 않은 fallback이다. 공개 후보가 아니며 독립 규칙으로 승격하지 않는다. 현재 지원하지 않는 문법도 새 규칙으로 억지로 분류하지 않고 `UNSUPPORTED`로 남긴다.

외부 참조가 일부 셀에만 존재하는 구조, 수식처럼 보이는 텍스트, `IFERROR` 같은 오류 처리 함수도 자동으로 “오류”가 되는 독립 규칙이 아니다. 전자는 현재 M4-A가 지원하지 않는 외부 문법과 연결되고, 후자는 계산 결과·업무 의도 없이는 정상 예외가 많다. 카탈로그에서는 보류 후보로만 다루며, 우선순위 count와 M4-B 공개 대상에 넣지 않는다.

## 우선순위 체계

카탈로그의 `business_impact`, `expected_frequency`, `implementation_cost`는 시장 통계나 발생률이 아니라 아래의 통제된 상대 등급이다. 각 후보에는 반드시 `priority_rationale`을 함께 기록한다.

| 값 | 의미 |
| --- | --- |
| `HIGH` | 업무 결과·검토 시간·신뢰에 큰 영향을 줄 수 있거나, 일반 업무 통합문서에서 현실적으로 자주 만날 수 있거나, 구현/검증 부담이 큰 경우 |
| `MEDIUM` | 영향 또는 빈도는 의미 있으나 통합문서 유형·구조에 따라 차이가 큰 경우 |
| `LOW` | 영향이 제한적이거나, 드물거나, 단순한 보조 신호인 경우 |

우선순위는 단순 합산 점수가 아니라 다음 순서로 판단한다.

1. 높은 업무 영향과 현실적인 발생 가능성
2. 낮은 오탐 가능성 또는 보수적으로 제외할 수 있는 명확한 조건
3. 사용자에게 설명할 수 있는 구조적 근거와 Excel 확인 방법
4. 명확한 다음 행동 및 향후 Approved Repair 연결 가능성
5. 계산·업무 맥락·보관 정책 없이도 안전하게 다룰 수 있는지

따라서 명시적 오류는 이미 가치가 있어도 우선순위가 자동으로 최고가 되지 않는다. 설명 가능한 silent formula error 후보가 위 조건을 충족하면 더 먼저 검토한다.

## 공통 품질 및 공개 게이트

모든 후보는 구현 전에 아래 프로필 하나와 연결된다. 프로필은 후보의 실제 성능을 주장하는 지표가 아니며, 해당 규칙을 공개하기 전에 충족·기록해야 할 최소 계약이다.

| Gate | 적용 | 필수 조건 |
| --- | --- | --- |
| `QG-S1` 정적 결정 규칙 | 파일 메타데이터, 명시 오류, 단순 형식/성능 | 합성 target·normal·unsupported 코퍼스, target 기대값 전수 일치, 명시 normal/unsupported에서 원치 않는 finding 0, 사전 성능 예산, 값 없는 근거·Excel 확인법·미공개 전환 규칙 |
| `QG-P1` 패턴/구조 추론 | 수식 패턴, 범위, 집계 | 위 코퍼스에 정상 예외·경계·혼합 구간을 추가하고, 사전 정한 후보 precision 90% 이상·target recall 85% 이상, 명시 제외 구조 false positive 0, 반복 안정성, 성능 비율 검토, 값 없는 설명과 한계. 수치 미달 또는 설명 불가 시 `WITHHELD` |
| `QG-V1` 버전 비교 | 두 파일 변화 | 짝지은 합성 이전/이후 파일, 비교 기준·파일 동일성·이전 파일 보관/삭제 정책, target/normal 변화 검증, 민감한 두 파일을 로그에 남기지 않는 출력, 성능/보관 승인이 없으면 `WITHHELD` |
| `QG-C1` 계산 엔진 | 순환참조·계산 결과 | 승인된 격리 계산 엔진, Excel 기준 결과와의 비교 코퍼스, 버전/재계산 설정, 네트워크 차단·일회성 저장소·시간/메모리 예산, 계산 불일치 원인 설명. 이 전에는 정적 결과 판정 금지 |
| `QG-B1` 업무·도메인 규칙 | 업무, 재무, 통계 | 사용자 제공 규칙 명세·적용 범위·정답 사례·정상 예외, 도메인 검토자, 익명 합성 코퍼스, 명확한 책임 경계. 업무 의도를 추정하거나 합성 정답을 고객 정답으로 일반화하지 않음 |
| `QG-A1` 자동화 기회 | 반복 업무 후보 | 명시적 사용자 동의가 있는 과정 관찰 또는 안전한 합성 흐름, 예상 절감이 아닌 반복 단계 근거, 개인정보/보관 정책, 자동화 제안과 실행을 분리. 관찰 근거 없이는 진단 finding으로 노출하지 않음 |

### 모든 게이트의 출력 및 실패 규칙

- 평가 코퍼스에는 target, normal, unsupported를 포함한다. 계산·버전·도메인 후보는 해당 전제조건이 충족된 뒤에만 코퍼스를 만든다.
- 성능 예산은 공개 전 **사전 선언**한다. M4-A.5의 현재 상대 2배 검토 기준은 세 워크로드 모두 초과했으므로 `CONDITIONAL`이다.
- 공개 가능한 설명에는 발견된 사실, 가능한 영향, 정상일 수 있는 조건, 이번 검사에서 확인하지 않은 범위, Excel 확인 방법이 있어야 한다.
- 원문 수식·셀 값·파일명·시트명·좌표·finding key는 서버 로그와 평가 산출물에 기록하지 않는다. 사용자 응답의 위치 표시는 향후 별도 개인정보·보관 검토의 대상이다.
- 품질, 성능, 설명 가능성, 개인정보 정책 중 하나라도 불충족하면 `exposure_status=WITHHELD`로 되돌린다. `PROTOTYPE` 또는 `PLANNED`라는 이유만으로 공개하지 않는다.

## 상태와 노출 상태의 분리

`current_status`는 엔진/구현 상태이고 `exposure_status`는 사용자 화면 공개 상태다. 두 값은 서로 대체되지 않는다.

| 필드 | 허용 값 | 의미 |
| --- | --- | --- |
| `current_status` | `IMPLEMENTED`, `PROTOTYPE`, `PLANNED`, `REQUIRES_CALCULATION_ENGINE`, `REQUIRES_VERSION_COMPARISON`, `REQUIRES_BUSINESS_CONTEXT`, `REQUIRES_DOMAIN_EXPERTISE`, `UNSUPPORTED` | 코드와 필요한 전제조건 상태 |
| `quality_gate_status` | `NOT_EVALUATED`, `PASSED_SYNTHETIC`, `CONDITIONAL`, `FAILED` | 해당 규칙의 공개용 품질 게이트 상태 |
| `exposure_status` | `INTERNAL_ONLY`, `M4_B_CANDIDATE`, `FREE_VISIBLE`, `WITHHELD` | 현재 또는 가능한 사용자 노출 상태 |

현재 M4 두 규칙은 합성 코퍼스의 정확성·예외·설명·안정성은 통과했지만 상대 성능 검토가 남아 있으므로 정확히 `PROTOTYPE / CONDITIONAL / INTERNAL_ONLY`이다. M4-B가 승인되어도, 별도 성능 결정을 통과하기 전에는 `M4_B_CANDIDATE`로 바꾸지 않는다.

`REQUIRES_VERSION_COMPARISON`은 M4-A.6에서 추가한 lifecycle 상태다. 이전 파일의 확보·동일성 판정·보관/삭제 정책·두 파일 비교 기준이 모두 필요한 후보에 사용한다.

### 실행 결과와 lifecycle 상태의 분리

`ABSTAIN`, `INSUFFICIENT_EVIDENCE`, `UNSUPPORTED_STRUCTURE`, `SKIPPED_TRUNCATED`, `FAILED`는 rule lifecycle 상태가 아니다. 한 번의 선택형 감사가 만든 **실행 결과**이며, 후보를 만들지 않는 fail-closed 결과다. `docs/28_M4B_PRODUCT_CONTRACT.md`의 실행 상태 계약을 사용한다.

따라서 `current_status=PROTOTYPE`인 규칙도 이번 실행에서 `ABSTAINED_INSUFFICIENT_EVIDENCE`가 될 수 있고, `current_status=PLANNED`인 규칙은 실행 자체가 불가능하다. 근거가 부족한 수식을 경고로 바꾸지 않는 것이 제품 신뢰 원칙이다.

## M4-B에 대한 보수적 제안

이 문서는 M4-B 구현 또는 노출 승인이 아니다. 이후 별도 승인에서 검토할 수 있는 범위도 다음으로 한정한다.

- 대상 후보: 합성 품질이 검증된 `FORMULA_PATTERN_OUTLIER`, `FORMULA_PATTERN_GAP` 두 rule code만
- 표현: 업무 오류·계산 결과·수정 수식이 아니라 “주변 수식 패턴과 다른 구조 후보”와 확인 방법
- 제외: `GENERIC_PATTERN_DRIFT`, 지원하지 않는 수식 문법, 계산 엔진이 필요한 판단, 자동 수정 제안
- 선행 결정: 30,000 수식에서 추가 1.4920초 및 2.198배~2.545배 상대 증가를 제한된 내부 베타에서 허용할지 인간 검토

기본 무료 결과와 M2.5 UI는 그대로 유지한다.

## 추천 다음 구현 배치 — 승인 요청 전의 제안만

아래는 사업 가치와 안전성 관점의 **추천 순서**일 뿐, 구현 승인이 아니다. 각 규칙은 자신의 `QG-P1` 또는 더 높은 게이트를 통과하고 별도 마일스톤 승인을 받아야 한다.

1. `FORMULA_NEW_ROW_NOT_EXTENDED` — 신규 행/기간에 수식이 연장되지 않은 구조 후보. 현재 gap 규칙과 겹치는 부분은 subtype/근거로 재사용하고, 독립 rule code는 명확한 행 추가 맥락을 입증할 수 있을 때만 만든다.
2. `FORMULA_PATTERN_GAP` 보강 — 수식 영역의 상수·빈 셀을 현재 rule code 안에서 더 넓은 정상 예외 코퍼스로 검증한다. 새로운 규칙 개수로 중복 산정하지 않는다.
3. `FORMULA_RANGE_BOUNDARY_DRIFT` — 집계/조회 수식의 끝점이 인접 패턴과 달라진 후보. 현재 `RANGE_BOUNDARY_DRIFT` subtype과 구별되는 독립 계약은 집계 의미와 정상 예외를 설명할 수 있을 때만 검토한다.
4. `AGGREGATE_CRITERIA_RANGE_MISMATCH` — 조건 범위와 집계 범위 길이/시작점의 구조 불일치 후보. 계산 결과의 오류 단정은 금지한다.
5. `SUBTOTAL_TOTAL_DOUBLE_COUNT_RISK` — 소계와 총계를 함께 포함할 가능성. 행 역할·정상 예외의 오탐 위험이 높아 우선 코퍼스와 보수적 제외 규칙이 필요하다.

`FORMULA_STORED_AS_TEXT_CANDIDATE`, `FORMULA_PARTIAL_EXTERNAL_REFERENCE_PATTERN`, `IFERROR_MASKED_ERROR_REVIEW_SIGNAL`은 카탈로그에 추가했지만, 각각 형식 예외·미지원 외부 문법·계산/업무 맥락 문제로 다음 구현 배치의 상위 후보가 아니다.

전월 파일 대비 수식 변경은 가치가 크지만, 이전 파일 확보, 같은 파일 계열 판정, 보관·삭제 정책이 없어 다음 배치에 포함하지 않는다. 업무·재무·통계·자동화는 더 많은 규칙보다 먼저 명시적 맥락 계약을 설계해야 한다.

## 장기 의사결정 순서

1. M4-B 여부: 현재 두 프로토타입의 성능 비용과 제한된 내부 노출 여부를 별도 승인한다.
2. M4 다음 배치: 위 추천 후보 중 하나씩, 정상 예외와 Excel 확인 방법을 먼저 설계한 후 품질 게이트를 통과시킨다.
3. M5: 사용자가 제공한 업무 규칙에 한해 업무 정합성을 검증한다. 파일 안에서 업무 의도를 추측하지 않는다.
4. M6: 계산 엔진과 버전 비교의 격리·충실도·보관 정책을 승인한 뒤에만 계산 결과 또는 이전 파일 차이를 다룬다.
5. M7: 정밀 검증과 승인된 변경 범위가 확정된 경우에만 별도 수정본·변경 내역·재검증을 설계한다.

이 순서는 “더 많은 경고”가 아니라, 신뢰 가능한 무료 진단에서 정밀 검증과 승인 기반 Repair로 이어질 수 있는 근거를 축적하기 위한 것이다.
