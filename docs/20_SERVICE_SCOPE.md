# 서비스 범위와 결과 해석 기준 — M2.5

## 현재 제공 상태

현재 WorkbookCare는 로컬 개발 환경에서 `.xlsx`와 `.xlsm` 파일의 **무료 정적 진단**만 제공합니다. 정밀 검증, 사용자 승인 후 수정, 자동화 의뢰, 신청 폼, 결제, 전문가 견적 요청은 화면에 준비 예정으로만 표시되며 동작하지 않습니다.

무료 진단은 AI API를 사용하지 않습니다. 매크로·VBA, Power Query, 외부 통합문서 연결은 실행하지 않으며, 진단 과정은 원본 파일을 수정하거나 다시 저장하지 않습니다. 파일 미저장, 자동 삭제, 암호화 저장, 보관 기간은 현재 로컬 구현으로 보장하거나 표시하지 않습니다.

## 무료 정적 진단의 범위

다음은 현재 검사합니다.

- 파일 구조와 시트 표시 상태
- 수식 문자열 안의 명시적 오류 토큰과 외부 통합문서 참조 표기
- 제한적인 숫자 텍스트, 병합 영역, 수식 복잡도·성능 위험 신호
- 매크로·표시 요소 존재 여부와 검사 안전 제한 도달 여부

다음은 검사하지 않습니다.

- 주변 수식의 일관성 및 수식 패턴 드리프트
- Excel 계산 결과, 캐시 값, 재계산 결과
- 업무 규칙, 원본 데이터의 의미, 회계·통계 모델의 정확성
- VBA·Power Query·외부 연결 실행
- 자동화 설계와 실제 파일 수정

M4-A에는 수식 패턴 후보 엔진이 존재하지만 기본값이 꺼진 내부 프로토타입이다. 현재 무료 Results 화면은 이 후보를 기본 제공·표시하지 않으며, 주변 수식 일관성 검사는 M4-B 승인 전까지 여전히 현재 무료 진단 범위 밖이다.

`scan_truncated = true`이면 안전 제한으로 일부 셀만 검사한 것입니다. 결과는 전체 파일 검사가 아닙니다.

## 탐지 확실도

`confidence`는 기존 내부 호환 필드이며 통계적 정확도나 보정된 확률이 아닙니다. 사용자 화면은 다음 탐지 근거 등급만 표시합니다.

| 화면 등급 | 현재 적용 기준 | 의미와 한계 |
|---|---|---|
| 직접 확인 | 파일 구조, 시트 상태, 수식 문자열의 특정 토큰처럼 규칙이 직접 확인한 사실 | 해당 사실의 존재를 뜻할 뿐, 계산 결과·업무적 정확성을 뜻하지 않음 |
| 패턴 추정 | `NUMBER_STORED_AS_TEXT`처럼 값의 형식과 제한된 주변 패턴을 함께 본 신호 | 의도적으로 텍스트인 식별자일 수 있으므로 사람 확인이 필요 |
| 참고 신호 | 병합 영역 과다·수식 수 과다처럼 유지보수 또는 성능 검토를 권하는 구조 신호 | 오류나 손실을 확정하지 않음 |

새 규칙에 숫자형 확실도를 사용자에게 보이려면, 표본·측정 방법·보정 기준을 별도 문서로 승인해야 합니다.

## 구조 위험 점수

화면의 `탐지된 구조 위험 점수`는 **규칙 기반 우선순위 점수**입니다. 금전 손실 확률이나 Excel 계산·업무 규칙의 정확도 점수가 아닙니다.

현재 계산식은 다음과 같습니다.

- 중요 finding: 건당 16점, 최대 48점
- 주의 finding: 건당 6점, 최대 36점
- 참고 finding: 건당 1점, 최대 10점
- 매크로 포함: 6점
- 외부 참조: 건당 2점, 최대 6점
- 안전 제한으로 검사 중단: 4점
- 총점 상한: 100점

표시는 `낮음`(0–19), `보통`(20–44), `높음`(45–69), `높음 · 우선 확인 필요`(70–100) 순으로 우선합니다. 이 가중치는 경험적 운영 가설이며 실제 오류율·손실액·수정 난이도를 보정한 값이 아닙니다.

## 수정 가능성 분류

| 화면 분류 | API 값 | 현재 의미 |
|---|---|---|
| 안전 수정 후보 | `SAFE_CANDIDATE` | 규칙상 정해진 변경 후보이나, 현재는 실제 수정하지 않음 |
| 사용자 확인 필요 | `CONFIRMATION_REQUIRED` | 업무 의도에 따라 유지·변경 판단이 달라질 수 있음 |
| 전문가 검토 필요 | `EXPERT_REVIEW` | 수식 의미·파일 충실도·매크로 등 별도 검토가 필요할 수 있음 |
| 정보 제공 | `INFORMATION_ONLY` | 구조·성능 참고 신호이며 즉시 수정이 필요하지 않음 |

수정 가능성은 현재 finding을 분류한 값이며 수정 성공 보장이나 제공 중인 수리 기능을 뜻하지 않습니다.

## Repair-readiness와 해결 경로

결과의 `해결 경로 검토 대상` 수는 `SAFE_CANDIDATE`, `CONFIRMATION_REQUIRED`, `EXPERT_REVIEW` finding 수를 합친 값입니다. 이는 현재 파일에서 향후 수정 또는 정밀 검증 전에 사람의 판단이 필요한 항목 수를 보여 주는 보조 지표이며, 자동 수정 가능 건수·구매 가능 서비스 수·수정 성공 보장이 아닙니다.

각 finding은 기존 수정 가능성 분류에서만 파생한 선택적 `repair_readiness` 정보를 가질 수 있습니다.

| 상태 | 현재 화면 의미 | 향후 필요한 단계 |
|---|---|---|
| `REPAIR_CANDIDATE_AFTER_APPROVAL` | 향후 승인 후 수정 검토 대상 | 정밀 검증 → 변경 전 미리보기 → 사용자 승인 → 수정 후 재검증 |
| `USER_DECISION_REQUIRED` | 사용자 결정 후 수정 검토 대상 | 업무 의도 확인 → 정밀 검증 → 미리보기 → 승인 → 재검증 |
| `PRECISION_VERIFICATION_REQUIRED` | 정밀 검증 선행 대상 | 정밀 검증 → 수정 방법 검토 → 미리보기 → 승인 → 재검증 |
| `INFORMATION_ONLY` | 즉시 수정 대상 아님 | 현재 수정 경로를 제안하지 않음 |

이 정보는 새 진단 규칙이나 자동수정 엔진이 아니다. scanner는 기존 사실과 분류만 만들고, recommendation engine이 결과를 바꾸지 않는 결정론적 설명으로 경로를 보강한다.

향후 서비스 카탈로그에는 `APPROVED_REPAIR`가 준비 중으로 기록되어 있다. 제공 예정 산출물은 변경 대상·방법 미리보기, 사용자 승인 후 원본과 분리된 수정본, 셀·수식 단위 변경 내역, 수정 후 재검증 보고서다. 현재 이 산출물은 제공되지 않는다.

### 향후 검토 표시본 가설

M3에서 실제 필요성이 확인될 경우, 실제 수정 전 단계의 별도 `검토 표시본`을 검토할 수 있다. 이는 원본을 변경하지 않고, 별도 사본에 검토 목록과 제한된 Finding 위치 표식을 넣어 사용자가 Excel에서 확인하기 쉽게 하는 후보 산출물이다. 표식은 확정 오류가 아니라 **검토 신호**이며, 현재 제공 기능이 아니다.

표시본도 통합문서를 열고 다시 저장하는 작업이므로 모든 파일에 안전하다고 가정하지 않는다. 매크로, 차트·도형 등 고충실도 위험, 외부 시스템 의존성 또는 보존 안전성이 입증되지 않은 파일은 표시본 생성 대상에서 제외하고 위치 안내·CSV 또는 전문가 검토로 분기한다. 표시본 구현은 M3가 아니라 후속 승인된 파일 생성/충실도 범위에서만 검토한다.

## 추천과 서비스 카탈로그의 경계

`recommendation_engine.py`는 발견된 사실, 가능한 영향, 이번 검사에서 확인하지 않은 내용, 다음 기술적 검사 및 추천 서비스 코드를 제공합니다. 제공 예정 산출물·서비스 상태·베타 가격 범위는 `service_catalog.py`에서 별도로 관리합니다.

현재 추천 서비스 코드는 `PRECISION_VERIFICATION`이며 상태는 `PLANNED`입니다. 향후 `APPROVED_REPAIR`도 별도 서비스 코드와 예정 산출물로 관리합니다. 두 서비스 모두 현재 제공 산출물이 아닙니다.

## 가격 표시

가격은 결제 금액이 아닌 베타 가격 가설입니다. 화면은 단일 금액보다 작업 수준과 범위를 먼저 보여 주고, 예를 들어 `Standard · 29,000원 ~ 49,000원`처럼 표시합니다. 현재 결제는 진행되지 않으며, 범위와 가설은 `service_catalog.py`의 `BETA_PRICE_RANGES`에서 변경할 수 있습니다.

## 샘플 결과의 단일 기준

프론트엔드 샘플은 수동으로 작성하지 않습니다. `samples/demo-risky-workbook.xlsx`를 실제 scanner로 실행한 뒤, 별도 recommendation engine이 결정론적 안내 필드만 보강해 생성한 `apps/web/src/data/demo-result.fixture.json`을 사용합니다. 이 보강 과정은 finding·분류·수치·진단 규칙을 바꾸지 않습니다.

갱신 절차:

```powershell
apps\api\.venv\Scripts\python.exe scripts\generate_demo_fixture.py
```

fixture에는 생성 시각, 생성 원본, 생성 스크립트, scanner/rule-set 버전이 기록됩니다. API 테스트는 fixture의 finding들이 같은 sample scanner 결과와 일치하는지 확인하고, 프론트엔드 데모는 이 fixture만 읽으므로 백엔드 실행 여부와 무관하게 재현됩니다.

## 결과가 없는 경우

finding이 0개여도 파일이 정확하거나 문제가 없다는 뜻이 아닙니다. 화면은 다음 문구를 사용합니다.

> 현재 무료 검사 범위에서는 구조적 위험 신호를 발견하지 못했습니다. 수식의 업무적 정확성, 계산 결과, 업무 규칙 및 통계 모델은 검증하지 않았습니다.

대표 finding은 항상 `min(3, 실제 finding 수)`만 표시합니다. 나머지는 문제 유형별 실제 개수로 요약합니다.

## Action Category와 무료 직접 조치

M2.5 Extension의 Action Category는 기존 finding의 severity·repair class를 바꾸지 않는 안내 계층이다. 화면은 `수정 또는 확인 우선 권장`, `사용자 확인 필요`, `정밀 검증 필요`, `정보 제공`으로 표시한다.

무료 단계는 모든 현재 Finding에 발견 사실, 가능한 영향, Excel에서 확인하는 방법, 정상일 수 있는 조건, 조치를 우선 권장하는 경우, 현재 검사 한계를 제공한다. 사용자가 직접 해결할 수 있는 항목에는 직접 확인·수정 후 재검사를 우선 안내하며, 모든 경고를 유료 서비스로 연결하지 않는다.

## 사용자 처리 상태

`확인 전`, `확인함`, `수정 예정`, `무시`, `정상으로 판단`은 시스템의 품질 판정이 아닌 사용자의 화면 내 메모다. 현재는 React local state만 사용하며 DB, 계정, 서버 저장, 장기 이력, 결제·승인 상태는 만들지 않는다. 이 상태는 severity, Action Category, risk score, 가격, scanner 결과를 바꾸지 않는다.

## 수정 후 다시 검사

사용자는 Excel에서 직접 수정한 테스트용 파일을 다시 올려 같은 scanner와 rule set으로 재검사할 수 있다. 앱은 현재 열린 브라우저 화면의 이전 결과와 새 결과만 비교하며, 이전 원본 파일을 보관하지 않는다.

비교 key는 `rule_code`와 정규화된 sheet/cell 또는 range로 만든 `finding_key`다. 셀 값·수식 본문·파일 내용은 key에 넣지 않는다. 결과는 다음 세 표현만 쓴다.

- 이번 재검사에서 더 이상 탐지되지 않음
- 계속 탐지됨
- 새롭게 탐지됨

첫 표현은 해결 보장이 아니다. 시트 이름 변경·셀 이동은 새 Finding처럼 보일 수 있고, scanner/rule-set version이 다르거나 한 결과가 일부 검사라면 비교가 근사치일 수 있다. 계산 결과, 업무 규칙, VBA·Power Query·외부 파일 내용은 재검사하지 않는다.

## CSV 결과 다운로드

현재 결과는 브라우저에서 UTF-8 BOM CSV로 다운로드할 수 있다. CSV에는 검사 메타데이터, 무료 검사 범위, `scan_truncated`, Finding 위치·근거·Action Category·직접 확인 방법·검사 한계·사용자 처리 상태가 들어간다. PDF, 서버 저장소, 서버 측 보고서 생성은 제공하지 않는다.
