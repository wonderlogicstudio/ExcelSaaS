## 코덱스에게 전달할 실행 메시지

아래 작업을 ExcelSaaS 원본 제품 저장소에서 수행해줘. 별도 local-LLM worktree와 혼동하지 마.

### 첫 실행 단위: DELIVERY-ZIP-01

목표는 같은 수정 작업의 검증된 필수 결과물 세 개를 ZIP 한 번으로 다운로드하도록 제공하는 것이다. 지금 승인된 제품 작업은 이 단위 하나이며, 아래 후속 로드맵을 자동 실행하지 않는다.

1. 작업 전 확인
   - AGENTS.md와 현행 milestone의 최신 요약, 위 관련 리뷰·고객 산출물 계약부터 확인한다. 과거 문서 전체를 반복 탐색하지 않는다.
   - git status, 현재 브랜치/HEAD, 원격과의 차이, 기존 사용자 변경을 확인한다. 기존 변경을 덮거나 함께 stage하지 않는다.
   - 새 로컬 코드·증거에서 이미 해결됐는지 확인하고 중복 구현하지 않는다.
   - 현행 milestone에 이번 단위 범위를 기록한다. 기존 STOP 기록·검증 결과는 보존한다.

2. 원인 확인과 구현
   - 파일 생성, 세트 무결성 검사, API 응답, 프런트 Blob/링크/URL 해제, 다운로드 상태 처리를 확인한다.
   - 실제 브라우저 수령 문제가 제품 문제라고 미리 단정하지 않는다. 코드·응답 검증으로 확인한 것과 남은 원인 불확실성을 구분한다.
   - 기존 접근 통제·artifact 검증·만료·작업 상태를 재사용해 ZIP 다운로드를 구현한다.
   - 같은 owner/job/현재 승인 plan에 속하고 모두 READY인 필수 3파일만 묶는다. manifest는 현행 계약에 따라 보조로 포함할 수 있다.
   - ZIP 생성 때문에 원본/승인 계획을 변경하거나 수식 계산·수정을 다시 실행하지 않는다.
   - 누락·손상·만료·다른 owner 접근은 전체 ZIP 제공을 차단한다. ZIP 내부 경로와 이름도 안전하게 구성한다.
   - 개별 다운로드는 유지한다. 주요 버튼은 ZIP 한 번 다운로드로 단순화한다.
   - 응답 또는 다운로드 요청 성공을 '실제 수령 확인'으로 표시하지 않는다.
   - 계산/approval/원본 보존/후검증 게이트를 완화하지 않는다.

3. 표적 검증
   - 정상 세트 ZIP, 누락/손상/만료 세트 차단, 다른 owner 접근 차단, plan·artifact 일치, 압축 내부 파일명 안전성, 기존 개별 다운로드 유지에 필요한 의미 있는 테스트를 실행한다.
   - 프런트 변경 시 관련 테스트·타입 검사·빌드, 백엔드 변경 시 관련 pytest·Ruff를 수행한다.
   - 기존 PL/Builder/Reviewer 및 비용·재시도 규칙에 따라 한 번의 집중 리뷰를 진행한다.
   - 제품 코드 변경 없는 문서 작업에 제품 전체 회귀를 반복하지 않는다.
   - 실제 브라우저 수령/native Excel/관련 종단 검증은 코드 검토·동결 후 별도 확인 단위로 남긴다. 미실행은 NOT_RUN이다.

4. 결과 기록과 종료
   - 원인, 변경 파일, 실행 명령/exit code, 리뷰 결과, 생성·응답 검증 증거, 미검증 사항을 간결하게 기록한다.
   - 최신 요약에 실제 결과만 추가한다. 옛 FAILED/PARTIAL/NOT_RUN을 PASS로 바꾸지 않는다.
   - 검증된 해당 변경만 선별 local commit한다. 기존 별도 승인 조건에 따라 push·배포는 진행하지 않는다.
   - 최종 보고는 A4 1장 이내로 하고 다음 단위 DELIVERY-RECEIPT-01을 제안한 뒤 정지한다.

첫 단위 완료 기준:
- ZIP 다운로드 경로가 구현되어 있고 관련 테스트·타입/정적 검사·리뷰 통과.
- 승인된 같은 작업의 필수 3개 artifact만 포함.
- 누락/손상/만료/권한 오류 시 성공 ZIP을 제공하지 않음.
- 요청과 실제 수령의 상태를 혼동하지 않음.
- 실제 브라우저 수령과 Excel 재개봉을 아직 수행하지 않았다면 완료 주장에 포함하지 않음.

## 후속 순서 — 첫 실행의 승인 범위가 아님

### 1. DELIVERY-RECEIPT-01: 실제 수령 증명

코드 리뷰·동결 후 별도 승인된 환경에서 합성 파일로 업로드 → 진단 → 계획 → 승인 → 수정 → ZIP 수령을 수행한다.
ZIP을 풀어 필수 세 파일의 hash·값·수식·변경 기록·검증 범위와 원본 보존을 확인한다.
사용 가능한 native Excel에서 재개봉하고, 없으면 미실행으로 남긴다.
환경·인증·브라우저 제한 때문에 검증 못 한 항목은 구현 실패와 구분한다.
로컬/호스팅 증거는 구분하고 기존 클라우드 변경·배포 승인 조건을 지킨다.

### 2. BENCHMARK-01: 독립 업무 평가 기반

기존 합성 도구를 재사용한다. 새 엔진이나 동일 프로그램을 중복 작성하지 않는다.
먼저 독립 합성 파일 20~30개의 정상/오류/판단불가/미지원 구조와 정답·채점 단위를 확정한다.
할인, 소계, 수동 조정, 의도적 빈칸, 선행0 식별번호, 절대/혼합 참조, 월별/다른 시트 참조 등 정상 예외를 포함한다.
업무 정답은 원더로직의 검토 또는 독립 계산으로 실행 전에 확정한다. 결과에 맞춰 oracle을 변경하지 않는다.
개발용과 최종 평가용 파일을 분리한다.
탐지 precision/recall뿐 아니라 잘못된 수정, 정상 셀 변경, 거부·부분완료·실패, 처리시간을 각각 기록한다.
기존 진단 worker가 수정/UI를 검증한 것처럼 주장하지 말고, 수정·산출물에는 별도 평가 경로를 정의한다.

동일 파일 경쟁 비교는 공개 기능 범위 안에서 별도 실행한다.
파일 업로드/회원가입/구매가 필요하면 기존 권한 범위를 확인한다. 공식 소개만 읽은 결과를 실제 비교 PASS로 기록하지 않는다.
우리만 수행한 시험과 경쟁 제품에서도 수행한 시험을 구분한다.

### 3. UX-01: 최소 입력과 한국어 업무 설명

경리·영업관리·재고 담당자 역할로 AI가 화면을 점검하되 합성 사용자 평가라고 명시한다.
완료 여부, 입력/클릭 수, 용어 오해, 승인 판단에 필요한 근거, 실패 후 복구 경로를 기록한다.
사용자가 이미 제공한 정보를 다시 묻는 입력과 불필요한 셀주소/수식 입력을 줄인다.
검증된 수치만으로 수정 영향·연결 합계 변화를 설명한다. 미계산 영향은 추정 또는 미확인으로 표시한다.
승인·근거·안전 게이트를 클릭 수 절감을 이유로 제거하지 않는다.
AI 평가를 실제 고객의 신뢰·구매 의향 증거로 계산하지 않는다.

### 4. 출시 준비

앞 단위들의 실제 결과를 기반으로 첫 상품을 좁힌다. '모든 Excel 오류 자동 해결'을 약속하지 않는다.
고객별 접근, 보관/자동·즉시 삭제, 영속 주문·재접속·재다운로드, 장애 복구, 비용 한도와 결제·취소·보상 정책을 각각 검증한다.
임의로 production 차단을 해제하거나 테스트 PG를 실결제로 전환하지 않는다.
제한된 검수형 유료 시험에서 본인 검수 시간·고객 작업 시간·재작업·구매 반응을 측정한다.
