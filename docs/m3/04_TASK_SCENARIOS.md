# M3 과제와 합성 시나리오

## 시나리오 자산

| 시나리오 | 파일·결과 기준 | 목적 | 실제 scanner 기대 상태 |
|---|---|---|---|
| A — Mixed Findings | `samples/demo-risky-workbook.xlsx`, frontend demo fixture | 여러 심각도·수정 가능성·참고 항목이 섞인 현재 대표 결과 이해 | fixture 기준 12 findings, scanner `0.1.2`, rule set `2026.08.2` |
| B — Low or Zero | `samples/m3/low-or-zero-findings.xlsx` | “발견 없음”과 “파일이 정확함”을 구분하는지 확인 | 0 findings, risk band `low` |
| C — Re-validation | `samples/m3/revalidation-before.xlsx` → `revalidation-after.xlsx` | 재검사 표현의 의미와 한계 확인 | 이전 3건: 외부 참조/#REF!/숫자 텍스트; 이후 2건: #REF! 계속, `INDIRECT` 신규 |

세 파일은 합성 데이터다. `scripts/generate_m3_test_scenarios.py`가 B/C 파일과 JSON fixture를 다시 만들고, API fixture 테스트가 실제 scanner 출력과 비교한다. Scenario A는 기존 `scripts/generate_demo_fixture.py`의 scanner fixture를 사용한다.

## 핵심 과제 — 15~20분

### Task 1 — 첫 화면 이해 (Scenario A)

“화면을 10초 정도 본 뒤, 이 서비스가 방금 무엇을 확인했는지 설명해 주세요.”

관찰: 정적 진단임을 말하는지, 발견 결과를 요약하는지, 전체 Excel 정확성을 보장한다고 오해하지 않는지.

### Task 2 — 가장 먼저 볼 문제 (Scenario A)

“가장 먼저 확인해야 할 문제는 무엇이라고 생각하나요?”

관찰: 기본 카드에서 심각도·위치·제목을 읽는지, 위험 점수만으로 판단하지 않는지, Sheet/Cell을 찾는지.

### Task 3 — 검사하지 않은 범위 (Scenario A)

“이번 무료 진단이 확인하지 않은 것은 무엇인가요?”

관찰: 계산 결과, 업무 규칙, 회귀·통계 모델, VBA·Power Query, 자동화 설계 중 하나 이상을 구분하는지.

### Task 4 — Excel에서 확인하기 (Scenario A)

대표 Finding 하나를 가리켜 “이 항목을 실제 Excel에서 어떻게 확인하시겠습니까?”라고 묻는다.

관찰: 접힌 기본 카드에서 `자세히 보기`를 찾아 여는지, Excel 확인법과 이번 검사 한계를 찾는지. 진행자가 상세를 먼저 열어주지 않는다.

### Task 5 — 현재 제공 기능 구분 (Scenario A)

“정밀검증이나 자동수정 기능을 지금 바로 사용할 수 있나요?”

관찰: 준비 중 기능과 현재 무료 정적 진단을 구분하는지. 현재 제공 중으로 오해하면 P0 후보로 기록한다.

### Task 6 — 다음 행동 (Scenario A)

“이 결과를 실제 업무 파일에서 받았다면 다음에 무엇을 하시겠습니까?”

선택지를 먼저 제시하지 않는다. 필요하면 직접 확인, 직접 수정, 동료 문의, 전문가 의뢰, 정밀검증 사용, 무시, 수정 후 재검사 중 무엇을 말하는지 기록한다.

## 후반 모듈 — 시간이 남을 때만

### Task 7 — 낮은/없는 결과와 재검사 (Scenario B/C)

Scenario B를 보여준 뒤: “이 결과는 무엇을 뜻하고, 무엇을 뜻하지 않나요?”

Scenario C에서는 먼저 이전 파일을 진단한 후 이후 파일을 재검사해: “이 결과는 어떤 의미라고 이해하셨나요?”라고 묻는다.

관찰: “이번 재검사에서 더 이상 탐지되지 않음”을 업무적 완전 해결로 오해하지 않는지, 계속 탐지와 새 탐지를 구분하는지.

### Task 8 — 유료가치 (Scenario A)

가격을 보여주기 전에: “현재 무료 결과에서 해결되지 않은 부분은 무엇인가요?”, “어떤 결과물을 추가로 받는다면 비용을 지불할 이유가 생길까요?”라고 묻는다.

기록할 구체 결과물: 수식 정밀검증, 수정 후보, 변경 전 미리보기, 승인된 수정본, 변경 내역, 수정 전후 비교, 재검증 보고서, 전문가 검토.

참여자가 위치 확인의 어려움을 말했거나, 자유 응답을 모두 받은 뒤에만 다음의 **준비 중 개념**을 중립적으로 보여 줄 수 있다. 현재 제공 기능처럼 표현하지 않는다.

> “원본은 바꾸지 않고, 별도 검토 표시본에 진단 위치와 검토 목록을 표시해 준다면 어떤 점이 도움이 되거나 걱정되나요?”

추가 관찰: 시트명·셀 주소·Excel 이동 안내만으로 충분한지, 별도 사본의 셀 강조 또는 검토 목록이 실제 확인 시간을 줄일지, 복사본의 서식·매크로·내용 보존에 어떤 증거가 필요한지. 이 질문의 응답은 기능 구현 승인이나 구매 의향 확정이 아니다.

### Task 9 — 가격 반응 (Scenario A)

마지막에만 현재 베타 가격 가설을 보여 준다. “이 가격에서 반드시 포함되어야 할 결과물은?”, “비싸거나 싸다고 느끼는 이유는?”, “결제 전에 어떤 증거가 필요한가요?”, “비슷한 문제에 든 시간·비용은?”을 묻는다.

단일 ‘결제하시겠습니까?’ 질문만으로 전환 의향을 판단하지 않는다.
