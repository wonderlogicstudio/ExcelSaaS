# Market positioning

## Current market direction

The spreadsheet-AI market is moving from single-formula generation toward agents that build, edit, analyze, visualize, and automate complete spreadsheet workflows. Microsoft and Google now provide native AI inside Excel and Sheets, so a generic "chat with your spreadsheet" product has weak defensibility. Dedicated products are also emphasizing complete tasks, file uploads, reports, audit findings, privacy, and no-signup trials.

## Competitive reference points

| Reference | What it proves | Gap we should exploit |
|---|---|---|
| Microsoft Copilot in Excel | Native AI can build/edit workbooks, create formulas, charts, and PivotTables | Users still need independent pre-send assurance, fixed repair scope, and evidence outside a seat-based enterprise product |
| Gemini in Sheets | Native spreadsheet creation and formula assistance will become commodity | Do not compete on natural-language formula generation |
| Better Analyst / Formula Bot | A narrow formula tool can grow into a large data-analysis product; free tools and organic acquisition can work | Keep an extremely clear first job instead of expanding early into generic analytics |
| Ajelix | "Agentic" end-to-end spreadsheet output is now expected language | Use agentic execution internally, but sell verified outcomes rather than autonomy itself |
| ExcelErrorFinder | No-signup and browser-only privacy are compelling acquisition hooks | Pair privacy-first free scanning with a paid, scoped repair path |
| SaferSheets / Tracelight / PerfectXL | Audit evidence, exact locations, risk ranking, annotated files, and enterprise trust matter | Combine consumer-simple UX with professional evidence and transparent per-file pricing |

## Category choice

Do not position as:

- AI Excel chatbot.
- Formula generator.
- General data analyst.
- Template generator.
- File converter collection.

Position as:

> **Workbook diagnosis and approved repair.**

Korean positioning line:

> **엑셀을 고치기 전에, 무엇을 왜 고칠지 먼저 보여드립니다.**

## Differentiation stack

1. **Two-level privacy**
   - Quick scan in the browser where practical.
   - Deep scan only after explicit upload consent.
2. **Evidence-backed findings**
   - Exact location, rule, severity, impact, and confidence.
3. **Repairability classification**
   - Safe automatic fix / user confirmation / expert review.
4. **Quote before payment**
   - Exact included and excluded items.
5. **Change-set approval**
   - Users can deselect optional changes.
6. **Before/after verification**
   - Re-scan and change log.
7. **Human escalation**
   - Complex files become qualified consulting leads rather than failed automation jobs.

## Wedge strategy

Start with the moment immediately before a workbook is shared, submitted, or relied upon:

> "Run a pre-send check."

This is more urgent and measurable than "work faster with AI." Later, expand backward into cleanup and forward into governance.

## Landing-page message hierarchy

1. Outcome: catch hidden workbook risks before they cause a mistake.
2. Mechanism: upload or sample → diagnosis → exact quote → optional repair.
3. Trust: original untouched, no signup, no training, deletion policy.
4. Evidence: exact cells and issue categories.
5. Limits: no macro execution; expert path for complex files.
6. CTA: `무료로 검사하기`.

## Brand constraints

- Avoid generic purple AI gradients and robot imagery.
- Avoid using `Excel` as the core brand name.
- Use a calm, technical, financial-control visual language.
- Never invent customer counts, accuracy percentages, certifications, logos, or testimonials.
- A founder/expert narrative is acceptable only when factually supportable.

## Growth loop

1. Search-intent article or free tool addresses one concrete problem.
2. Visitor runs a no-signup scan.
3. Diagnosis creates a personalized reason to repair.
4. Repair outcome produces a before/after artifact.
5. User can share a privacy-safe report or recommend the tool.
6. Aggregated, non-sensitive issue statistics inform new tools and content.

## Initial acquisition pages

Create one focused page per high-intent problem rather than one broad AI page:

- Excel `#REF!` 검사 및 수정.
- 깨진 외부 링크 찾기.
- 느린 Excel 파일 원인 검사.
- 숨겨진 시트와 VeryHidden 시트 확인.
- 수식 패턴 불일치 찾기.
- 숫자가 텍스트로 저장된 셀 찾기.
- Excel 파일 보내기 전 점검.

Each page should lead to the same scan experience and use structured, truthful examples.
