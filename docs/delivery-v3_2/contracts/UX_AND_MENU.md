# 고객 인터페이스와 메뉴

## 목적 중심 진입

서비스 메인 CTA는 기존 무료 파일 진단을 유지한다. 작업 안에서 지원 가능하면 ‘수정 범위 확인’, 독립 진입으로 ‘두 자료 비교’를 제공한다. 나머지 메뉴(정밀검증·승인수정·재검증·자동화)의 의미는 유지하되 비어 있는 서비스처럼 운영하지 않는다.

- 정밀검증: 해당 작업의 기술/업무 검증 범위를 보여준다.
- 승인 기반 수정: READY profile만 범위 확인 가능, PAID 이후 정확한 plan 승인.
- 재검증: 직접 업로드 비교와 서비스가 변경한 파일의 후검증을 분리.
- 자동화: 첫 버전은 같은 방식의 새 작업 **수동 시작** 또는 상담 공급능력에 따른 경로. 다음 달 자동 덮어쓰기·무인 승인은 없음.

## 결과 목록

유형 요약 기본 + 전체 항목 표 대안. 한 유형의 설명은 한 번, leaf별 위치/차이/사용자 상태는 유지한다. 동일 제목으로 grouping해도 승인 범위는 개별 exact cells다. 전체 발견·반환 상세·생략·필터 표시 수를 구분하고 원 CSV/점수/무료·M4 경계를 보존한다. 필터 reset은 상태 reset이 아니다.

## 구매 앞·뒤의 문구

상품 카드에는 ‘수정본 포함’ 또는 ‘비교 보고서 전용·수정본 미포함’을 크게 표시한다. PLANNED/UNSUPPORTED/NOT_PURCHASED/WAITING_APPROVAL/FAILED/READY를 모두 자물쇠 하나로 표현하지 않는다. 가격 미정이면 ‘예상 가격’으로 몰래 구매 CTA를 만들지 않는다.

유료 화면의 입력/출력/조건 비교는 다음처럼 배치한다.

```text
구매 상품: 승인 기반 수정 패키지
결제: 완료     파일 변경: 승인 대기
받을 파일: 수정본.xlsx · 변경내역.xlsx · 재검증.html

셀  | 변경 전(타입 포함) | 변경 후 | 근거 | 예상 영향
...
[대상 다시 선택] [취소 절차] [이 변경계획 승인]
```

승인 클릭 이후 ‘실행/검증/납품’ 실제 상태만 표시한다. 백엔드 완료 단계가 없으면 가짜 %·남은 시간 금지. 버튼 하나를 ‘결제 및 자동 수정’으로 합치지 않는다.

## 산출물 화면

수정 완료 화면에는 필수 세 파일 목록과 각각의 검증 상태·생성시간·만료·재다운로드·삭제·문의 동선을 보여준다. 하나라도 누락이면 성공 다운로드 세트로 게시하지 않는다. 비교 완료 화면은 원본을 바꾸지 않았다고 명시하고 변경승인 영역을 내지 않는다.

## 모바일·접근성

목록에서 상세로 이동하고 돌아올 때 필터·스크롤·focus 복구. 모바일에서는 전후 비교를 읽기 순서에 맞춰 세로 배치하며 단순 축소하지 않는다. 키보드 승인·취소·검토 경로, focus trap 회피, 오류와 pending 안내, 긴 수식 copy/view를 검증한다. 색상만으로 오류·승인 상태를 구분하지 않는다.

## 예시와 실제

공개 합성 예시에는 항상 ‘예시’ 표시. 실제 식·숫자·시트 설명은 소유권 및 유료 범위에 따라 제공한다. 계산 trace가 없으면 ‘수식 구조 설명’, 실제 실행 기록이 있으면 engine/version/coverage와 함께 ‘실행 근거’로 표시한다.
