# 비교 상품·업무별 자료·상담 경계

두 자료 비교의 V3.1 입력·키·금액·중복·자료오류·단건 보고서 요구는 유지한다. `reference/previous_v31.zip`과 추출해 둔 `reference/v31_contracts/`가 기준이며, 이 패키지의 수정 계약은 비교 알고리즘을 바꾸는 지시가 아니다.

## 확실히 하지 않을 일

A와 B가 다르다는 이유로 A를 B로 수정하지 않는다. 금액 차이가 곧 손실/오류가 아니며 키 중복은 임의 합계/매칭으로 숨기지 않는다. 자료오류 행을 지워 한쪽누락을 만들지 않는다. 불명 값을 0으로 바꾸지 않는다. 같은 비교 재다운로드에는 재과금하지 않는다.

고객이 B를 기준자료로 선언하더라도 기존 비교 주문에는 원본 수정이 포함되지 않는다. 명세서 동기화는 새 repair profile·권한·정책·가격·별도 승인이 필요한 장기 후보다. 이번 D05에 추가하지 않는다.

## 매출·재고·원가·미수금의 공급 방식

|고객 목표|필요 정보|현재 경로|
|---|---|---|
|내 Excel 구조/수식 후보 확인|파일 하나|무료 진단, 지원 profile이면 승인 수정|
|우리·거래처 명세 차이 확인|공통키·같은 금액 기준의 두 표|대사 상품|
|수량×단가 수식 복원|동일업무를 적용할 기준수식·대상·정책|RP02 안에서 가능 여부; 세액/회계정답 자동 추정 금지|
|판매파일로 실제 재고 확정|기초·전체 수불·단위·조정·실사|자료 부족이면 판정 불가; 별도 상담/후속 profile|
|원가 적정성|BOM·수율·단가·배부·기간 정책|상담 공급능력 있을 때 범위 확정|
|부분입금/과입금 배분|청구·입금·상계·정산 정책|N:M은 이번 exact-key 상품 밖|
|새 자동화 서식 제작|현재 흐름·원하는 산출물·입력 예시|원본 관리서식이 없어도 상담 시작 가능, 판매는 담당자 전제|

상담 OFF일 때 개인정보 첨부·결제·납기 약속을 받지 않는다. 상담을 연 경우 계약된 산출물·테스트·사용법·수정회차·지원 주체가 필요하며 ‘Codex가 만들어 준다’는 개발 방식이 고객 납품 책임을 대신하지 않는다.

향후 순서는 매출→재고→원가→미수금의 요구/반복성/지불의사에 따라 profile을 검증한다. 지금의 bounded 수정을 구현하기 위해 네 ERP 엔진을 먼저 만들지 않는다.
