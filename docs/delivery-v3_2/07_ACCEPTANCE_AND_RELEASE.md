# 제품별 완료 판정

## 핵심 승인 수정의 필수 조건

1. RP01과 RP02의 입력→무료 적합성→범위/가격→sandbox 결제→정확한 계획→별도 승인→사본 변경→후검증→필수 세 파일 수령을 실제 앱으로 수행한다.
2. 변경 0개/전체거부/미지원/plan변경/자료변경/승인만료/취소/결제조회불명/후검증실패를 성공 납품과 구분한다.
3. 원본 hash 불변, 승인된 business patch set 일치, 예고된 보조 part만 변경, 필요한 계산 검증 실행, 미검증 산출물 격리.
4. 다른 고객/비교 SKU/환불/만료/조작 링크는 수정본에 접근 불가. 재시도/재다운로드는 중복 청구 불가.
5. 실제 타깃 Excel 재개봉/표시/계산/서식 검증, 독립 고정 정답과 계산 일치, 정상 예외와 보존 시험 통과. 사용 불가능하면 NOT_RUN으로 남기며 live 차단.
6. 새 보관/로그/승인 기록 정책·실계약·가격·고객지원·운영 접근이 검증·승인되어야 live ready.

## 비교 상품의 필수 조건

V3.1의 exact-key/자료오류/중복/금액·행수/보고서·권한·결제복구를 유지한다. 이 상품에서 B값은 정답이 아니며 수정본이 생기지 않는다. 비교 상품만 ready이면 `COMPARISON_ONLY_READY`로 한정한다.

## 시험 단계를 구분한다

PACKAGE_CHECKED / LOCAL_UNIT / INTEGRATION / BROWSER / EXCEL_REFERENCE / PG_SANDBOX / PROVIDER_LIVE / REAL_USER_OBSERVED를 각각 기록한다. 한 단계가 다른 단계의 근거가 아니다. 테스트 수·합성 100%로 실제 모든 파일 정확도나 시장성 주장을 하지 않는다.

## 공개 심사

핵심 수정 판매가 미준비인데 다른 상품의 성공으로 대체하지 않는다. 수정 상품이 차단되면 ‘준비 중/미지원’으로 정직하게 표시한다. 공개 범위 결정은 owner가 하고, 다음 단계·배포·고객 초대는 자동 진행하지 않는다.

기술상 필요한 모든 시험 중 하나라도 미실행이면 해당 영역 전체 PASS로 쓰지 않는다. 운영 불확실성은 로컬 합성 개발을 막을 이유가 아니라 **운영 공개 gate**다.
