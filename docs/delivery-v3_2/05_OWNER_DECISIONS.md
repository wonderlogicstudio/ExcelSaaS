# 사람이 결정할 사항

개발 방법·테스트 작성·버그 수정은 Codex가 맡는다. 다음은 사람이 결정해야 한다.

|항목|개발 중 기본값|live 전 필요한 결정|
|---|---|---|
|핵심 완성 범위|승인 수정 RP01/RP02; 비교는 독립 유지|실제 먼저 공개할 SKU 목록|
|가격|test 금액만, 실제 가격 UNAPPROVED|상품 포함/제외·총액·과금 단위|
|변경 전 취소|기본 설계 제안: 실행 전 전체 거부는 취소 가능|고객에게 공개할 환불/취소 문구와 검토|
|기술 납품 실패|고객 재과금 없이 재시도 또는 보상|자동 취소/보상 조건·처리 기한|
|입력/plan/출력 보관|로컬 synthetic 설정만|각 TTL·삭제·재생성 범위·비용|
|PG 및 계정|공식 sandbox가 없으면 adapter/mock 구분|실계약·키·실금액 시험 승인|
|계산 호환성|프로필별 독립 기준으로 개발|대상 Excel 버전과 수용시험 결과|
|상담 납품|판매 OFF|담당자·산출물·납기·수정회차·지원 여력|
|미지원 수식/고충실도 파일|해당 수정 주문 차단|완화가 아니라 신규 프로필 검증 승인|
|운영 접근·민감자료|기존 경계 유지|새 개인정보 처리·고객 접근권한·법률 검토|

이 표는 법률 판단이나 환불 의무의 확정이 아니다. 실제 정책과 적용법 검토 없이 ‘환불 불가’를 코드에 고정하지 않는다. 고객이 유료 계획을 본 후 실행 전 취소할 수 있는 정책은 악용/지원 비용이 있을 수 있으므로 측정하되, 안전한 승인을 강요하는 방식으로 막지 않는다.

세 단계의 승인: **개발 묶음 승인(소유자)** / **실제 상품 공개 승인(소유자)** / **자기 파일의 정확한 변경 승인(고객)**. 서로 대신할 수 없다.
