# D08 — 상품별 종단 수용시험·핵심 완성 판정

## 목표

문서가 아니라 실제 구매·승인·수정·납품 흐름으로 완성 범위를 입증하고 사람이 공개를 결정할 수 있게 한다.

범위: 공통; 공개SKU별 선행 조건

선행: D07

## 먼저 읽을 파일

[공통 계약](../08_CODEX_WORKING_RULES.md)과 현재 AGENTS/milestone/관련 review, 아래 두 문서만 기본으로 읽는다.

- [07_ACCEPTANCE_AND_RELEASE.md](../07_ACCEPTANCE_AND_RELEASE.md)
- [02_CUSTOMER_OUTPUTS.md](../02_CUSTOMER_OUTPUTS.md)

## 구현 지시

1. 새 synthetic holdout·정상예외·RP01/RP02·실패 계약으로 앱→API→engine→private artifact E2E를 실행한다. 비교 상품을 공개 범위에 포함할 때만 D05의 비교 E2E를 추가한다. 비교가 OFF인 것은 승인 수정 상품의 출시를 차단하지 않지만 비교 완료로 기록하지 않는다.
2. sandbox 결제 후 승인/선택변경/거부/만료/재접속/다운로드·재다운로드를 실행하고 output files를 열어 검증한다.
3. Excel reference·파일 보존·계산/업무 scope·모바일/키보드·동시성·데이터 삭제·부정권한을 독립 reviewer 기준으로 기록한다. 패키지 테스트를 제품 테스트로 대체하지 않는다.
4. 상품별 readiness와 missing evidence를 분리한 release_manifest를 만든다. 비교만 ready이면 수정 경로가 완성됐다고 하지 않는다.
5. M3 사용자관찰·M3.5 구매증거가 없으면 PENDING/DEFERRED를 유지한다. 내부 수용시험은 가능한 만큼 완료하며 판매 시작·초대는 별도 승인으로 남긴다.
6. 기존 완료기록을 보존한 최종 review/운영 인수인계/다음 유지보수 범위를 만들고 여기서 정지한다.

## 필수 검증

- 핵심 완료 판정: 두 repair profile의 필수 3파일 검증. 비교도 공개할 때는 comparison 필수 2파일을 별도로 검증
- negative approval/payment/validation/download matrix
- same origin hash와 signed plan receipt 대조
- 서버 실제 최소지원범위와 표시 일치
- NOT_RUN/PENDING/FAILED를 성공으로 변환 없음

## 사용자가 확인할 행동

1. RP01/RP02 실제 수정본·변경내역·후검증을 받아본다.
2. 비교 상품을 공개하면 수정본이 아님을 확인하고, 공개하지 않으면 판매 OFF를 확인한다.
3. 상품별 공개 여부와 남은 위험을 승인한다.

## 제외

자동 공개·새유료기능·수요/매출 실적 조작·다음 마일스톤 자동 실행.

## 산출/정지

실제 코드·연결된 UI/API/산출물과 검증 근거. `reviews/D08.md`, owner_action, delivery-progress delta. `ENGINEERING_VERIFIED_AWAITING_OWNER`, `REUSED_AWAITING_OWNER`, `PARTIAL`, `BLOCKED` 중 실제 판정. 필수 미실행은 별도 표시. 다음 묶음 자동 실행 금지.
