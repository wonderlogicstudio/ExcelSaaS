# D06 — 상품별 결제·변경승인·실패복구·재수령

## 목표

결제 뒤 고객이 정확한 변경을 승인하고 검증된 필수 산출물을 중복 과금 없이 받게 한다.

범위: 공통; 수정은 D04, 비교는 D05 선행

선행: D02

## 먼저 읽을 파일

[공통 계약](../08_CODEX_WORKING_RULES.md)과 현재 AGENTS/milestone/관련 review, 아래 두 문서만 기본으로 읽는다.

- [contracts/PAYMENT_APPROVAL_DELIVERY.md](../contracts/PAYMENT_APPROVAL_DELIVERY.md)
- [02_CUSTOMER_OUTPUTS.md](../02_CUSTOMER_OUTPUTS.md)

## 구현 지시

1. 기존 L05/작업 owner/PG/원장을 재사용한다. 상품별 선행 engine와 deliverables readiness가 없는 quote 및 live 결제를 차단한다.
2. 공식 sandbox 승인·조회·취소·중복webhook·응답유실을 처리한다. credentials 부족은 NOT_RUN으로 분리하고 mock을 live증거로 쓰지 않는다.
3. PAID 이후 상세 plan을 공개하지만 승인 전 작업은 WAITING_APPROVAL. approval snapshot/digest/expiry와 entitlement/SKU/원본 버전을 서버 검증한다.
4. 변경 선택 수정/거부/승인만료/전부미선택/삭제/환불 경로를 구현한다. 변경 범위가 넓어지면 새 quote/approval, 기술 재시도는 추가 청구 없음.
5. 수정 주문은 세 파일 전부 validation PASS일 때만 delivery success, 비교는 별도 두 파일. artifact-ready와 job-success와 payment를 분리한다.
6. 취소/권리회수/만료 도중 완료된 결과는 게시하지 않고 보상·문의·재시도 원장으로 복구한다. 재방문 주문목록은 최소 범위로 제공한다.

## 필수 검증

- PAID but no approval→no patch/download
- compare entitlement cannot repair
- stale input/plan/profile/subset/approval rejected
- doubleclick/webhook duplicate/out-of-order/payment unknown 복구
- all rejected/no changes/partial failure→not successful repair
- same purchase retry/download no recharge
- mandatory artifact missing/cancel before publication 차단

## 사용자가 확인할 행동

1. 결제 뒤 파일 변경이 승인대기인지 확인한다.
2. plan을 승인한 뒤 세 파일을 받는다.
3. 거부·실패·재방문에서 요금과 결과를 확인한다.

## 제외

실금액·환불정책 법적 확정·새클라우드 계약·live 공개.
