# D01 — 상품·산출물 경계와 기존 진단 UX 통합

## 목표

고객이 무료 진단, 비교 보고서, 승인된 수정본의 차이를 화면에서 이해하고 기존 결과 기능이 유지되게 한다.

범위: 공통

선행: 기존 프로젝트. 새 전면 재검증 단계 없음

## 먼저 읽을 파일

[공통 계약](../08_CODEX_WORKING_RULES.md)과 현재 AGENTS/milestone/관련 review, 아래 두 문서만 기본으로 읽는다.

- [01_PRODUCT_AND_SCOPE.md](../01_PRODUCT_AND_SCOPE.md)
- [contracts/UX_AND_MENU.md](../contracts/UX_AND_MENU.md)

## 구현 지시

1. 현행 코드/리뷰와 L01~L08 진도를 한 번 대조하고 acceptance별 재사용 근거를 남긴다. 전체 과거 문서 재독이나 새 초기화 금지.
2. 기존 catalog/API response 타입을 재사용하여 product_id, capability status, deliverable kinds, includes_repaired_workbook를 구분한다. 원격 catalog의 PLANNED를 구현 없이 AVAILABLE로 바꾸지 않는다.
3. 무료·대사·수정 상품의 제목/범위/받는 파일/제외/다음 행동을 기존 화면에 반영한다. 미구현 수정은 명확히 준비 중이며 결제 불가다.
4. 기존 L01의 전체/상세/생략/필터 수, 재검사 completeness, CSV 수식해석 방어와 그룹/전체표/모바일을 재사용하고 실제 남은 결함만 수정한다.
5. 그룹 확인과 변경승인 UI를 분리하고 진단 상태를 approval 데이터로 매핑하지 않는 회귀시험을 만든다.

## 필수 검증

- 상품 카드·API·CSV의 산출물 명칭 일치
- 미구현 수정 상품 구매 불가
- 그룹화 전후 leaf/score/CSV 불변
- 세분화된 개수/부분검사/필터0건 안내
- 다른 기능 progress 불변; UI keyboard/mobile

## 사용자가 확인할 행동

1. 무료 결과의 위치를 찾는다.
2. 비교에는 수정본이 없고 수정 패키지에는 세 파일이 있는지 읽는다.
3. 준비 중 기능이 구매되지 않는지 확인한다.

## 제외

실제 파일수정·계산엔진·PG·운영 배포·새 규칙 추가.

## 산출/정지

실제 코드·연결된 UI/API/산출물과 검증 근거. `reviews/D01.md`, owner_action, delivery-progress delta. `ENGINEERING_VERIFIED_AWAITING_OWNER`, `REUSED_AWAITING_OWNER`, `PARTIAL`, `BLOCKED` 중 실제 판정. 필수 미실행은 별도 표시. 다음 묶음 자동 실행 금지.
