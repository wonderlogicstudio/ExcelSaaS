# D04 — 승인된 사본 수정·후검증·세 파일 납품

## 목표

범위가 검증된 계획을 별도 사본에만 적용하고 실제 수정본·변경내역·후검증을 하나의 검증된 패키지로 만든다.

범위: 수정

선행: D03

## 먼저 읽을 파일

[공통 계약](../08_CODEX_WORKING_RULES.md)과 현재 AGENTS/milestone/관련 review, 아래 두 문서만 기본으로 읽는다.

- [contracts/PATCH_AND_VALIDATION.md](../contracts/PATCH_AND_VALIDATION.md)
- [02_CUSTOMER_OUTPUTS.md](../02_CUSTOMER_OUTPUTS.md)

## 구현 지시

1. production에서 발급 불가한 내부 synthetic grant/approval fixture로 엔진을 검증한다. 현재 API의 실제 결제/승인을 우회하는 공개 테스트 토글 금지.
2. 지원 inventory의 최소 patch writer와 비대상 member/셀/서식 검증을 구현한다. 원본 storage key와 수정 출력 key를 분리한다.
3. 필요 cache/계산 관계 변경을 사전 계획한 allowlist로 처리하고 계산용 engine save본을 검증 없이 납품하지 않는다.
4. 원본불변·patch 동등·실제 후계산·참조·새 오류·policy expected 및 원/변경부 보존을 수행한다. 검증 실패는 quarantine다.
5. 수정본.xlsx, changes.xlsx, verification.html, manifest를 같은 source/plan/output hash로 결합해 원자적으로 게시한다. 고객용 changes의 민감정보를 운영 로그에 내지 않는다.
6. 재시도·동시worker·취소 fence·누락 report·부분성공에서 정상 납품 차단을 구현한다. 기존 artifact/다운로드 기능을 재사용한다.

## 필수 검증

- RP01 한 타입변환 + RP02 실제 빈수식 복원
- source hash 동일·target set 정확·untouched cells/styles 동일
- 금지 part/차트·확장/서명 등 unsupported 거부
- 필수 파일 하나 누락시 READY 금지
- calc failure/unauthorized side effect/partial patch quarantine
- late completion after revoke·중복 실행 하나의 logical delivery

## 사용자가 확인할 행동

1. 별도 수정본을 Excel에서 연다.
2. 변경내역과 실제 셀을 대조한다.
3. 재검증 범위·원본 불변·실패 차단을 확인한다.

## 제외

원본 overwrite·실고객 납품·미검증 파일 게시·3파일 대신 보고서로 성공 대체.

## 산출/정지

실제 코드·연결된 UI/API/산출물과 검증 근거. `reviews/D04.md`, owner_action, delivery-progress delta. `ENGINEERING_VERIFIED_AWAITING_OWNER`, `REUSED_AWAITING_OWNER`, `PARTIAL`, `BLOCKED` 중 실제 판정. 필수 미실행은 별도 표시. 다음 묶음 자동 실행 금지.
