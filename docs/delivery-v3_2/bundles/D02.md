# D02 — 한 파일 수정 적합성·업무 확인·불변 입력

## 목표

지원 안 되는 파일/의도를 결제 전에 구분하고 수정 가능한 정확한 원본·필드·앵커·대상 버전을 고정한다.

범위: 공통·수정

선행: D01

## 먼저 읽을 파일

[공통 계약](../08_CODEX_WORKING_RULES.md)과 현재 AGENTS/milestone/관련 review, 아래 두 문서만 기본으로 읽는다.

- [contracts/REPAIR_ELIGIBILITY.md](../contracts/REPAIR_ELIGIBILITY.md)
- [contracts/SECURITY_OPERATIONS.md](../contracts/SECURITY_OPERATIONS.md)

## 구현 지시

1. 기존 인증·작업·R2/DB·파일 검증을 재사용한다. 새 durable state가 필요하면 local adapter부터 구현하고 운영 비용 승인은 별도로 남긴다.
2. 한 파일 수정용 input/preflight/job와 owner binding을 추가한다. 원본 hash/inventory와 정책 버전·선택 위치를 저장한다. 원본 overwrite API 금지.
3. RP01은 사용자 확인된 금액/수량 필드, RP02는 기준수식·빈 target·동일업무 적용 확인을 받는다. 후보가 0이면 수정 quote 불가다.
4. 지원 파일·수식·정밀도·지역 형식·매크로/외부 연결·target 종류·whole workbook 계산 coverage를 fail-closed로 검사한다. D03의 계산 프로필 증거가 아직 없으면 PRELIMINARY_ONLY/UNSUPPORTED로 남기고 수정 가능·견적 가능으로 표시하지 않는다. 이후 D03 검증 결과를 이 gate에 연결한다.
5. 기존 비교 input과 동일 저장/검증 서비스를 재사용하되 input 목적과 상품 소유권을 분리한다. TTL/취소/미구매 projection을 연결한다.

## 필수 검증

- owner 위조/원본 바꿔치기/만료/동시 업데이트 거부
- ID 00123·비용12원·날짜·빈값·초과정밀도 RP01 거부
- 진짜 blank와 빈문자열/formula/상수 구분
- 지원 안 되는 part·외부 함수·동적참조 거부
- 정책/기준수식 미확인과 NO_ELIGIBLE_CHANGES 결제 차단

## 사용자가 확인할 행동

1. 원본 한 파일로 수정 경로에 들어간다.
2. 금액열과 ID열의 처리 차이를 본다.
3. 수정 불가 이유와 다음 준비 행동을 확인한다.

## 제외

미지원 프로필 우회·업무정답 추정·실고객 업로드·자동원본 변경.

## 산출/정지

실제 코드·연결된 UI/API/산출물과 검증 근거. `reviews/D02.md`, owner_action, delivery-progress delta. `ENGINEERING_VERIFIED_AWAITING_OWNER`, `REUSED_AWAITING_OWNER`, `PARTIAL`, `BLOCKED` 중 실제 판정. 필수 미실행은 별도 표시. 다음 묶음 자동 실행 금지.
