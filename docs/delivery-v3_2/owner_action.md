# D01 사용자 확인

## 최신 확인 — 예상값 연결과 실제 베타20개 대조 완료

베타를 새로고침하면 파일 업로드 후 무료 검사와 별도 수식 패턴 검사가 자동 실행됩니다.
agent가 이미 고유20개를 실제 업로드하여72개 위치·규칙·세부 유형과 대조했습니다. 전체 재검사는 필요 없습니다.

1. 01번 샘플을 올려 **수식 패턴 후보4개 / 무료0건**을 확인합니다.
2. 수식 결과의 유형 묶음에서 ‘개별 위치’를 펼쳐 셀과 탐지 근거가 읽기 쉬운지 확인합니다.
3. 03번에서 **별도 수식 후보4개 / 무료49건**이 구분되고 무료49개가 한 유형으로 묶이는지 확인합니다.
4. 정상 대조10번 또는20번은 **수식 후보0개**이며, ‘확인함’이 수정 승인으로 바뀌지 않는지 확인합니다.

18번 E13/F22에는 정답표의 후보/정상 범위 중복2건이 있습니다. 원본 예상표와 기존 승인 예외는 보존했습니다.
연속 업로드는 기존 요청 제한을 따릅니다. 전체 시험 및 실제 베타 검증 증거는 `reviews/D01.md`와
`reviews/evidence/D01-m4-hosted.json`에 있습니다. 원격 push는 하지 않았습니다.
**다음 한 단위 제안: D02 — 파일 수정 적합성·업무 확인·불변 입력. 승인 전 실행하지 않습니다.**
아래 M4 미연결 설명은 이전 상태이며 최신 검증으로 대체되었습니다.

## 최신 상태 — 베타 직접 검증 완료, M4 연결은 미해결

agent가 로그인된 베타에서 합성 21개를 직접 업로드해 무료 결과를 대조했다.
03번 49건·11번 59건·나머지18개 0건·demo12건이 로컬과 일치한다. 동일 오류는 한 유형으로 접혀 있고 위치는 보존된다.
이전의 ‘로그인 브라우저 미연결/사용자 업로드 대조 필요’ 기록은 아래의 과거 상태다.
M4 예상72건은 별도 검사이며, 현재 사이트에서는 실행할 수 없어 미검증으로 남는다.

확인할 행동은 제품 판단에 한정한다. 20개 파일을 다시 수동 검사할 필요는 없다.

1. 베타의 03번 또는 11번 결과에서 한 유형으로 묶인 표시가 원하는 방식인지 확인한다.
2. ‘개별 위치’를 펼쳐 위치·근거를 읽고, 확인함이 변경 승인이 아니라는 안내를 확인한다.
3. 무료0건의 ‘수식 검증 미수행’ 안내가 검사 범위를 충분히 설명하는지 확인한다.

이 이슈의 다음 한 단위 제안: 기존 Access 보호를 유지한 **별도 M4 검사 연결·합성20개 예상값 대조**.
현재 비활성 경계를 바꾸므로 명시 승인 전 실행하지 않는다. D02는 기존 로드맵 추천으로만 보존하며 자동 실행하지 않는다.
새 코드·배포·원격 push 없이 직접 검증 증거만 추가했다. 기존 기록은 아래 보존한다.

## 현재 베타 확인 — 동일 오류 한 묶음 표시

**https://workbookcare-beta.wonderlogic-studio.workers.dev/** 에 새 버전 `673f2895-2142-4215-8024-9acb14fa53ae`를 반영했다.
03번에서 무료 49건이 나온다는 사용자 확인을 반영했고, 이번에는 표시 방식을 수정했다.

1. 베타를 새로고침한 뒤 기본 팩 `samples/03_미수금_채권관리.xlsx`를 올린다. **1개 유형으로 묶음 · 위치 49건**이며 49개 카드가 처음부터 나열되지 않는지 확인한다.
2. **개별 위치 49개 보기**를 펼쳐 시트·셀을 확인하고, 위치 한 개를 펼쳐 근거와 처리 상태를 확인한다. 접으면 한 묶음으로 돌아가야 한다.
3. **전체 항목 표**와 **진단 결과 CSV**에는 49개 위치가 유지되는지 확인한다. 유형의 확인함은 개인 처리 상태이며 변경 승인이 아니다.

로컬 실제 브라우저 1440/390·전체 회귀는 통과했다. 베타 수정 후 로그인 조작은 사용자 확인으로 남긴다.
M4 예상값 72건은 별도 내부 검사 결과이고 hosted M4는 계속 비활성이다. 원본/점수/CSV·무료/M4 분리는 유지했다.
기존 Access·비공개 저장소·API 인증과 지속 베타 배포 승인은 그대로다. 새 기능 활성화나 원격 push는 하지 않았다.
다음 한 단위는 **D02 — 파일 수정 적합성·업무 확인·불변 입력** 추천만 유지하며 승인 전 실행하지 않는다.

## 최신 보완 확인 — 무료 0건과 M4 미실행 구분

기존 베타에서 새로고침한 뒤 합성 파일만 사용한다.

1. M4 파일을 올려 ‘무료 구조 검사: 발견 0건’, 실제 읽은 셀·수식 문자열 수와 별도 수식 검증 미수행 안내를 확인한다. 0건을 정상 수식 판정으로 해석하지 않는다.
2. `samples/demo-risky-workbook.xlsx`를 실제 업로드한다. 로컬 실제 API의 양성 대조 결과는 12건이다. 베타에서도 이 파일이 0건이면 내용 대신 화면의 검사 개수·규칙 버전만 알려준다. ‘샘플 결과 보기’는 이 업로드 검증을 대신하지 않는다.
3. 부분 검사 또는 셀 내용이 없는 파일이 전체 검사 완료/정상으로 보이지 않는지 확인한다.

M4 수식 패턴 검사는 기존 비활성 경계를 유지한다. 별도 엔진의 hosted 실행 검증은 완료하지 않았다.
아래는 앞선 D01 확인 기록으로 보존한다.

## 현재 확인 주소 — 후속 베타 배포 완료

**https://workbookcare-beta.wonderlogic-studio.workers.dev/** 에서 기존 Cloudflare Access 로그인 후
새로고침한다. D01 웹 버전 `9748b413-0acd-4a57-a0fd-9a5e3324f3db`가 100% 적용됐다.
아래 네 가지 확인 행동은 이제 이 베타 주소에서 수행한다. 합성 샘플만 사용한다.
연결된 브라우저가 없어 로그인 후 화면 확인은 사용자 확인 항목으로 남아 있다.
배포 자체와 Access 302는 확인했고, Cloud Run API 변경/실제 hosted 업로드 검증은 수행하지 않았다.
새 베타 배포 승인은 프로젝트 완료까지 지속된다. 다음 개발 단위 D02 승인은 아직 없다.

아래는 배포 전 로컬 검토 기록과 재현 방법이다.

현재 승인: **D01만**. 판정: **ENGINEERING_VERIFIED_AWAITING_OWNER**.
로컬 구현 커밋: `40e2e8998beef87cb844c1fc400f1e75eced2fa1`. 원격 push·공개 배포 없음.

로컬 확인 화면: http://127.0.0.1:5187 (로컬 API 8187). 합성 샘플만 사용한다.
이 세션의 검토 서버가 종료됐다면 아래의 재현 명령을 사용한다.

1. **샘플 결과 보기**를 눌러 유형 설명을 펼치고 개별 시트·셀 위치와 근거를 찾는다.
2. **유형별 보기 ↔ 전체 항목 표**, 시트/상태 필터를 바꾼 뒤 CSV를 받는다. 유형의 ‘확인함’이 개인 상태만 바꾸고 구매나 변경 승인이 되지 않는지 읽는다.
3. **두 자료 비교** 안내에서 보고서 두 파일과 ‘수정본 미포함·B는 정답 아님’을 읽고, 수정 패키지에는 **수정본 XLSX·변경내역 XLSX·재검증 HTML** 세 파일이 예정돼 있는지 확인한다. 두 상품이 준비 중이며 구매되지 않아야 한다.
4. 휴대폰 너비에서도 표 제목·위치·초점이 읽히는지 확인한다. 필요하면 로컬 합성 `artifacts/verification/d01/synthetic-many-findings.xlsx`로 재검사해 **전체 150 / 상세 120 / 생략 30** 및 신규·미탐지 확정 불가 안내를 확인한다.
