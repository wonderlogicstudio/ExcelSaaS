# 누락·편향 검토와 이번 수정

## 판정

V3.1의 ‘두 자료 입력부터 결제와 보고서 수령까지’는 완결된 상품 설계다. 그러나 승인 기반 수정을 계속 뒤로 미루면서 이를 전체 제품 최종본이라고 부르면 원래 목적과 어긋난다. 이번에는 **비교를 폐기하지 않고, 보고서 상품과 수정 상품을 분리하며 수정 납품 경로를 구현 범위로 복원**한다. 이는 대사의 상업성이 검증됐다는 주장도, 모든 수식 자동수정이 쉬워졌다는 주장도 아니다.

## Git 점검의 의미

2026-09-12 확인한 GitHub main은 `47e5e54f2316e09a44e4395dd31c7afdf9803472`다. 해당 catalog의 Approved Repair와 Precision Verification은 PLANNED이며, 확인한 main.py는 scan/formula-audit 경로를 제공한다. 이 사실은 원격 snapshot의 상태이며 현재 PC의 더 최신 구현 여부를 판정하지 않는다. 로컬 working tree, review와 실제 API를 먼저 확인한다. 참조: [기술·저장소 근거](research/SOURCES.md).

이번 작업은 문서/첨부 검증과 읽기 전용 Git 확인이다. 제품 코드·운영 자원·실결제·실고객 파일은 변경하지 않았다. 사용자 보고 H3 완료는 그대로 계승하며 남은 운영 근거가 있는지는 배포 전 해당 항목만 확인한다.

## 출시 범위를 새로 혼동하지 않는다

`repair_scope_complete`, `comparison_scope_complete`, `operations_verified`, `owner_release_approved`, `commercial_signal_observed`를 독립 기록한다. 비교 상품만 먼저 판매하는 명시적 승인이 가능하지만 이는 **부분 상품 출시**다. ‘WorkbookCare 승인 기반 수정까지 완성’은 RP01/RP02의 필수 납품 시험이 모두 통과해야 한다. 같은 방식으로 실제 사용자 수요를 시험 자동화가 대신하지 않는다.

## 비용과 전환의 가설

수정본·변경내역·후검증을 한 가격으로 제공하는 것이 고객 기대를 명확하게 할 것이라는 설계 판단이다. 가격·지원 비용·환불 악용 가능성은 미검증이다. 수정 전 취소 정책, 보관기간, 실제 납품 담당자를 사람이 확정하기 전 live 판매를 켜지 않는다. 과장된 오탐·불안 문구·가짜 확률·무료 근거 회수로 결제를 유도하지 않는다.
