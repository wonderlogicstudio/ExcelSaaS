## 내부 설계 대조에서 보완한 사항

- 보고서와 수정본의 상품/권한/필수 파일을 분리했다. 비교 자료 B는 정답 또는 자동 덮어쓰기 원천이 아니다.
- 결제·진단 확인상태·정책 확인·파일변경 승인을 각각 분리했다.
- 원본·plan·선택 patch set·버전·유효시간을 실행과 결합하고, 변경된 계획에는 과거 승인을 쓰지 않는다.
- 수정본 누락·후검증 실패·취소/환불 경합은 성공 납품을 차단한다. 같은 작업의 기술 재시도·재다운로드는 중복 청구하지 않는다.
- 계산 기준이 아직 없는 D02는 임시 적합성 상태만 허용한다. D03 실제 프로필 확인 전 유료 실행을 열지 않는다.
- 핵심 수정 프로필 둘의 수용시험과, 선택적인 비교 상품 수용시험은 분리했다. 비교 OFF를 수정 미완료로 혼동하지 않는다.
- 원본 데이터는 비공개 고객 변경내역에 필요한 범위로만 포함하고, 운영 로그/피드백에는 저장하지 않는다.
- 원본120개/CF·UXR 요구와 기존 완료 기록을 삭제하지 않고, 이번 한정 범위만 추가 acceptance로 연결했다.

## 합성 산출물의 의미

예시의 기대값 27,000/24,000/9,500원, 합계 51,000→60,500원은 고정한 합성 조건의 독립 산술값과 생성 라이브러리 결과를 대조한 것이다. 실제 고객의 업무 정답 또는 Microsoft Excel reference 실행 결과가 아니다. 예시 파일은 별도로 생성한 사본이므로 **WorkbookCare의 최소 OOXML 패치·전체 파일 보존 엔진이 구현됐다는 증거도 아니다**. 원본과 비교해 달라진 XML part를 manifest에 공개했다.

## 미수행/환경 한계

- 실제 WorkbookCare 로컬 앱·Cloudflare·R2·Cloud Run·PG·사용자 계정에 변경하지 않았으며 제품 E2E를 실행하지 않았다.
- Microsoft Excel 재개봉/재계산, 실제 PG sandbox/live, 실사용자 관찰·수익성 검증은 NOT_RUN이다.
- 브라우저 환경에서 file:// 직접 탐색이 차단되어 HTML 본문 set_content로 실행했다. Windows 더블클릭·OS 클립보드 왕복·다운로드 후 실제 Excel 열기는 미검증이다.
- 자동 브라우저의 접근성 검사/레이아웃 확인은 수동 스크린리더·모바일 실기기 수용시험을 대체하지 않는다.
- 실제 카드 결제·환불·개인정보 보관·납품 운영 정책은 소유자 확정과 법률/PG 검토가 필요하다.

## 재현

도구의 텍스트 입출력은 UTF-8로 고정했다. 패키지 루트에서 `python tools/verify_package.py`, `python tools/test_contract_oracle.py`를 실행한다. Playwright/Chromium이 이미 준비된 개발환경에서는 `python tools/check_guide_browser.py`를 실행할 수 있다. 테스트 도구는 앱의 실행 스크립트가 아니며 검사 결과는 고객 납품 승인에 사용할 수 없다. 도구 실행 결과를 이 패키지의 JSON 파일로 직접 리다이렉트하지 않는다(검사 중인 파일을 동시에 비우는 것을 방지).
