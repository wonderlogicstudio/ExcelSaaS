## 보고와 승인

각 묶음의 완료 보고는 `reviews/Dxx.md`, 사용자 확인은 `owner_action.md`, 추가 진도는 `delivery-progress.json`에 남긴다. 예시 JSON은 템플릿일 뿐 기존 progress를 덮어쓰지 않는다.

사용자는 3~5개의 실제 행동(예: 결제 뒤 수정이 대기인지, 승인 후 세 파일이 생기는지, 원본이 그대로인지)을 확인한다. 보통 버그는 Codex가 같은 묶음 안에서 고치고 다시 시험한다. 라이브 PG·리소스 과금·가격·환불·공개·실고객 파일·원격 push는 별도 승인이다.

클릭 복사 실패 시 텍스트 상자를 클릭하고 Ctrl+A, Ctrl+C로 복사한다. 텍스트 파일 다운로드도 제공한다. 도구 실행은 사용자의 로컬 Python 환경에서 `python tools/verify_package.py`로 패키지 자체 검사만 가능하다. 이 검사는 앱·Excel·PG를 검사하지 않는다.

## 완료를 세 가지로 읽는다

- `IMPLEMENTED`: 관련 코드 존재.
- `ENGINEERING_VERIFIED`: 해당 실제 시험이 통과. 미실행 시험은 NOT_RUN.
- `LIVE_READY`: 상품별 필수 납품 + 운영 + 가격/PG/개인정보 + 사람 승인 충족.

문서 또는 예시가 존재하는 것은 위 어느 상태의 자동 근거도 아니다.
