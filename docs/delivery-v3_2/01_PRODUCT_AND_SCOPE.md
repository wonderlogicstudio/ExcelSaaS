# 큰 방향과 출시 경계

## 한 업무를 끝까지 완성한다

핵심 경로의 한 업무는 **“지원되는 내 엑셀의 특정 문제를 확인하고, 승인한 수정이 반영된 별도 파일을 받아 다시 검증한다”**이다. 모든 Excel 기능·ERP·업무 규칙을 동시에 만드는 뜻이 아니다. 대사 상품의 한 업무는 두 값 기반 명세의 차이를 설명하는 것이며 수정 상품과 다르다.

`DIAGNOSIS` → `ELIGIBILITY` → `QUOTE` → `PAID` → `EXACT_REPAIR_PLAN` → `CHANGE_APPROVAL` → `PATCH_COPY` → `POST_VALIDATION` → `DELIVERY`

승인 기반 자동수정은 **명세에 포함**한다. 현재 구현 여부는 로컬 코드와 시험으로 별도 판정한다. 결제와 변경 승인을 같은 상태나 버튼으로 합치지 않는다. 원본 파일을 덮어쓰는 기능은 계속 금지한다.

## 상품 경계

- `APPROVED_REPAIR`: 핵심 완성 대상. 지원 프로필의 선정·견적·결제·정확한 계획·선택 승인·변경·후검증·수령·실패 보상까지 구현한다.
- `TWO_FILE_COMPARISON`: V3.1의 범위를 보존한 독립 상품. 같은 정책의 관측자료를 비교하며 정답 수식·업무 기대값·수정본을 포함하지 않는다.
- `PRECISION_VERIFICATION`: 검증 활동/메뉴와 권한을 유지한다. 별도 유료 보고서 SKU를 자동 추가하지 말고, 현재 판매할 패키지의 포함 범위에 명시한다.
- `REVALIDATION`: 무료 직접 재검사와 유료 후검증을 구분한다. 수정 패키지 후검증에는 추가 요금을 청구하지 않는다.
- `AUTOMATION_CONSULTATION`: 기본 판매 OFF. 자료만 받아 놓고 자동 납품을 약속하지 않는다.

## 첫 수정 프로필 두 개

1. `RP01_NUMERIC_TEXT_FIELD_V1`: 사용자 확인 금액/수량 필드에 한정된 숫자형 텍스트→숫자 변환. ID·선행0·날짜·단위 혼합은 제외.
2. `RP02_APPROVED_FORMULA_RESTORE_V1`: 사용자가 업무적으로 적용 가능한 기준 수식을 선택하고 누락 셀의 정확한 번역 수식을 승인한 경우 복원. 주변 다수결은 정답 근거가 아니다.

프로필 두 개의 유료 종단 수용시험을 핵심 완료 기준으로 한다. RP01만 구현하고 범용 수식 수정 완료로 표시하지 않는다. RP02 계산/보존/호환성이 통과하지 않으면 미완료로 남기되, 독립적으로 완성된 다른 상품의 출시 여부는 사람이 별도 결정한다.

## 범위를 크게 되돌리지 않는다

IF/IFERROR/SUMIF는 화면 예시다. 공통 수식 구조와 지원 Registry를 유지하고 검증된 복합 조합을 다룬다. 이번에는 함수 목록을 임의로 확대하거나 IF를 IFS로 무조건 변환하지 않는다. 두 자료 차이를 B값으로 덮어쓰기, 임의 업무 정답 생성, N:M 입금 배분, 재고수불·BOM·원가배부, 통계 예측, 무인 반복 수정, 구독·팀 협업은 아직 별도 승인이다.

이미 구현한 것의 삭제·진도 초기화가 아니라 **상품별 산출물 계약과 안전한 수정 경로의 복원**이다. 실제 공개 SKU는 준비 상태와 운영 승인으로 결정한다. 소스/정답표/기존 H3 완료를 재작성해 제품을 완성시켜서는 안 된다.

## 고객의 확인을 혼동하지 않는다

‘확인함/정상으로 판단’은 진단 목록의 개인 처리 상태다. ‘비교 기준 확인’은 업무 정책 동의다. ‘결제’는 구매 권리다. ‘이 변경 승인’만 해당 계획을 실행할 권한이다. 네 상태는 서로 다른 필드·이벤트·버튼이다.
