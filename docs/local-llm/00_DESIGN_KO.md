# WorkbookCare 로컬 LLM 확장 설계
작성: 2026-09-27 · 단위: LOCAL-LLM-PREP01 · 상태: 승인 검토용 제안
이번 승인: 사전 작업 정리와 설계 문서 작성. 설치·모델 실행·제품 구현·배포 승인이 아니다.

## 1. 제품 목표와 성공의 의미
Excel을 모르는 고객이 문제와 변경 예시를 이해하고, 정확한 변경을 승인한 뒤 원본과 분리된 수정본 XLSX·변경내역 XLSX·재검증 HTML을 받는다.
LLM 도입 자체가 성공 기준은 아니다. 기존 규칙과 설명만 사용한 방식보다 고객 이해·안전한 처리 범위·운영 효율이 좋아지는지 비교한다.
품질·상업성은 아직 가설이며, 이번 문서로 정확도·매출·유료 출시 준비를 입증하지 않는다.

## 2. 고객 흐름
1. 기존 무료 진단: 위치·근거·CSV·위험 점수와 비교 기능을 유지한다. 기본 진단에 LLM 호출을 추가하지 않는다.
2. 선택한 문제의 설명: 무엇이 다른지, 어떤 업무 결과에 영향을 줄 수 있는지, 현재 확인하지 못한 부분을 설명한다.
3. 수정 후보와 질문: 확인된 문맥으로 후보를 제안하고 필요한 업무 기준만 질문한다. 셀 주소·수식 직접 입력을 기본 요구하지 않는다.
4. 독립 검증: 지원 여부, 참조·수식 제약, 실제 계산·영향 범위, 파일 보존 가능성을 검증한다.
5. 정확한 변경 승인: 모든 변경에 접근할 수 있게 하고 실제 검증된 전후 예시와 영향 범위를 공개한다. 질문 답변·대표 예시 확인·결제는 실행 승인이 아니다.
6. 기존 실행·납품: 승인에 묶인 계획만 적용하고 재검증 후 세 파일을 제공한다. 다운로드 요청 성공과 실제 수령 확인은 구별한다.
검증 불가·정보 부족·모델 실패는 이유를 설명하고 보류한다. 지원되지 않는 수정을 판매 가능으로 표시하지 않는다.

## 3. 책임과 신뢰 경계
| 구성요소 | 허용 책임 | 금지 책임 |
|---|---|---|
| 기존 분석기 | 파일 검증, 패턴 후보와 근거 추출 | 패턴 차이를 업무 오류로 단정 |
| LLM | 문맥 해석, 후보 수식, 근거 참조, 쉬운 설명, 필요한 질문 | 파일 수정, 코드·도구 실행, 정답·실행 허가 결정 |
| 독립 검증 코어 | 원본에서 근거 재확인, 허용 규칙·계산·보존 검사, 실행 가능성 판단 | 모델의 자신감·사용자 동의를 정답으로 인정 |
| 기존 계획·승인·실행 | 계획 digest·원본 hash·권리에 결합된 정확한 승인과 사본 생성 | 미지원 후보를 기존 프로필로 위장 |
| 고객 | 업무 기준 제공, 검증된 정확한 변경에 대한 실행 동의 | 기술적 검증을 대신함 |

흐름: 제한된 증거 묶음 → LLM 제안 → 구조 검증 → 독립 규칙/계산 검증 → 기존 계획 → 고객 승인 → 기존 실행/재검증.
프로덕션의 검증 코어는 시험 정답표에 접근하지 않는다. 시험 정답표는 결과 평가에만 사용한다.
같은 모델을 두 번 호출하거나 다른 모델에게 찬성을 받는 것은 독립 검증이 아니다.
재계산 성공·패턴 경고 소멸만으로 업무상 정답을 증명하지 않는다. 업무 기준이 근거와 맞지 않거나 부족하면 보류한다.

## 4. 기존 자산과 최소 변경
| 자산 | 재사용 | 추가 필요 |
|---|---|---|
| apps/api/app/formula_patterns.py | outlier·비교 위치·정상 예외·검사 한계 | 제한된 문맥 입력 어댑터 |
| apps/web/src/lib/repairReview.ts, repairProposals.ts | 발견 항목 선택과 지원 여부 구분 | 이후 승인된 범위에서 후보·질문 표시 |
| apps/api/app/delivery_plan.py, delivery_calculation.py | 계획 무결성, 허용 계산 문법과 영향 확인 | 일반 행 참조 교체의 별도 검증 규칙 |
| apps/api/app/delivery_execution.py | 원본·계획·권리·후보 ID에 묶인 승인/실행 전 검사 | 새 규칙의 유효성 증거와 기존 gate 연결 |
| apps/api/app/delivery_patch.py, delivery_artifacts.py | OOXML 사본 패치, 비대상 보존, 재검증·세 파일 | 새 규칙의 대상 변경/계산 cache 범위 검증 |
RP02는 빈 셀 복원, RP03는 제한된 월별 참조 교체다. 기존 수식의 일반 행 참조 교체는 현재 지원되지 않는다.
일반 IF 수식도 모두 계산 가능한 것이 아니다. 계산기 allowlist에 없는 조합은 실행 차단한다.
엔진 삭제·대규모 재작성·임의 수식 평가·원본 덮어쓰기·비교 파일 B의 정답화는 범위 밖이다.

## 5. 첫 시험 범위와 모델 계약
첫 유형은 동일 표/시트에서 주변과 다른 행을 참조하는 수식. 입력과 정답은 합성 자료만 사용한다.
후보 생성 실험과 실제 수정 지원을 분리한다. 첫 실험은 파일을 전혀 변경하지 않는다.
입력: schema_version, case_id, source_digest, 대상 셀/현재 수식, 제한된 이웃 셀, 필요한 헤더·값, 업무 기준과 출처, 탐지 근거 ID, 누락 문맥, 지원 범위.
전체 통합문서·파일 경로·비밀·고객 식별자·정답표·변이 위치 힌트는 모델에 주지 않는다. 셀 텍스트는 명령이 아닌 비신뢰 데이터다.
출력: schema_version, case_id, decision(PROPOSE/ASK/ABSTAIN), target, proposed_formula(없으면 null), evidence_ids, explanation_ko, questions, uncertainty_reasons.
PROPOSE도 실행 권한은 없다. 설명은 주장마다 근거 ID와 연결하며 없는 근거를 만들어내면 거부한다.
주소·수식 길이·출력 크기·필드·열거형을 제한한다. 초안 상한: 문맥 4K token, 출력 1K token, 질문 2개, 요청 1개 동시 처리.
JSON 오류·추가 필드·잘못된 주소·도구 호출·실행 문자열·근거 불일치·timeout은 실패/보류로 기록한다. 자동 무한 재질문은 금지한다.
고객 질문 답변이 바뀌면 후보와 검증 계획을 다시 만들고 이전 정확한 승인은 무효화한다.
M4의 기존 값 없는 API 계약은 유지한다. 문맥 수집은 향후 별도 내부 경계로 설계하며 이번에 API를 넓히지 않는다.

## 6. 독립 검증의 순서
1. 입력 원본 digest·위치·현재 수식·증거 일치 및 파일 안전성 검사.
2. 동일 표 경계·헤더·업무 기준·예외·절대/혼합 참조를 검사. 다수 패턴만으로 자동 교체하지 않는다.
3. 허용된 참조 변경만인지 구문 구조로 확인. 연산자·상수·함수·열 변경, 외부 참조·이름 정의·미지원 문법은 거부.
4. 검증 코어가 허용 규칙으로 독립 도출한 후보와 모델 후보를 대조. 복수 후보/의도 미확정이면 보류.
5. 지원 엔진의 실제 계산·영향 범위·순환/오류·제약 검사. 저장 cache나 LLM 예상값을 실제 계산으로 표시하지 않는다.
6. 기존 계획 생성과 정확한 승인 gate, 실행 직전 재검사, 승인 외 변경 방지.
7. 사본 재검증에서 대상·비대상 셀, XML/서식/내부 part, 계산 결과, 해결/잔여/신규 발견을 확인.
구체적인 수식/표 허용 집합은 fixture/계약 단계에서 고정하며 그 전에는 새 규칙을 지원 상태로 등록하지 않는다.

## 7. 로컬 실험과 운영 보안
2026-09-27 이전 읽기 전용 조사: RTX3060 12GB(당시 여유 약10.4GiB), i7-8700, RAM31.92GiB(여유15.37GiB), C 여유 약474GiB.
API venv Python3.13.15; Python3.10 보존. 당시 확인한 경로에서 Ollama/LM Studio/llama-server 미발견. 전체 설치 부재를 보증하지 않는다.
Qwen3-14B Q4_K_M을 주 후보, Qwen3-8B Q4_K_M을 비교 후보로 둔다. 14B 채택/VRAM 적합성/속도는 미검증.
공식 14B GGUF 약9GB라는 이전 조사 정보는 설치 전 다시 확인한다. 파일 크기는 총 실행 메모리가 아니다.
공식 출처:
- https://huggingface.co/Qwen/Qwen3-14B-GGUF
- https://huggingface.co/Qwen/Qwen3-8B-GGUF
- https://github.com/ggml-org/llama.cpp/releases
설치 후보는 별도 폴더의 Windows CUDA llama.cpp 바이너리와 GGUF. 시스템 PATH·기존 API venv·GPU driver를 변경하지 않는다.
제안 위치: 프로젝트 내 tools/local-llm/<version>/ 및 models/local-llm/<revision>/ (실제 설치 단위에서 ignore/용량/권한 확인).
설치 전 정확한 release/파일명/revision·license·다운로드 URL·해시·총 용량·무결성 확인 방법을 고정한다. 현재 미확정이므로 설치 준비 완료가 아니다.
서비스 바인딩은 loopback만, 공유 서버·클라우드 연결 없음. 모델 실행 계정/프로세스에 workbook 수정·shell/tool 호출 경로를 부여하지 않는다.
loopback만으로 접근 제어가 충분하다고 보지 않는다. 이후 연결 단계에서 로컬 인증·Origin/요청 제한과 프로세스 종료/timeout을 검증한다.
추론 시 외부 통신·telemetry·원격 fallback을 금지하고 관찰 가능한 시험으로 확인한다. 다운로드 통신은 설치 단위에만 한정한다.
원문 prompt/셀/수식/모델 원문을 운영 로그에 남기지 않는다. 성능 로그는 버전·크기·시간·분류·거부 사유만 기록한다.
합성 상세 증거는 지정 시험 폴더에만 두고, 모델·cache·대용량 산출물을 Git에 넣지 않는다.
로컬 개발 시험 성공은 hosted beta에서 고객 파일을 로컬 PC로 보내도 된다는 승인이 아니다. 서비스 배치 구조·보관/삭제·동시성·장애 운영은 별도 승인 과제다.

## 8. 품질과 상업성 평가
비교군: A 기존 규칙+템플릿, B 같은 근거/검증 코어+8B, C 같은 근거/검증 코어+14B.
모든 군은 같은 사례·업무 기준·검증 제약을 사용한다. 후보 품질 개선과 새 검증 규칙 효과를 따로 집계한다.
우선순위는 잘못된 실행 차단 → 정확한 후보와 적절한 보류 → 이해도 → 시간/비용이다.
지표: 정확한 후보 수/분모, 오수정 통과 수, 예외 보존, 정보 부족 질문 적합성, 불필요한 보류, 근거 없는 설명, JSON 성공률.
성능: cold start, warm p50/p95, timeout/OOM, peak VRAM/RAM, 입력/출력 tokens, 재시도와 CPU offload 여부.
초기 목표(제안): warm p95 30초 이내, 60초 timeout, 동시1, 통제 반복에서 OOM0. 미달은 성능 실패로 보고하며 정확도 기준을 낮추지 않는다.
고객 검증(별도 승인): Excel 초보 참가자가 문제·변경·남는 불확실성을 자기 말로 설명할 수 있는지와 완료시간/필수조작/운영자 개입을 비교한다.
초기 탐색 목표(제안): 합성 과제 참가자5명 중4명 이상이 핵심3항목을 정확히 설명. 통계적 상업성 증명으로 사용하지 않는다.
실제 비용: 추론/전력·장비상각 + 운영자 검토시간 + 재작업/지원 + 파일처리/보관 비용을 성공 납품 건수로 나눈다.
가격·결제율·지불의사는 별도 가설/사용자 승인 사항이다. 고객의 정확한 변경 승인률을 구매 의사나 정답률로 계산하지 않는다.
LLM이 안전성을 유지하며 이해도 또는 운영 효율을 개선하지 못하면 도입 보류/설명 전용 축소를 선택한다. 큰 모델 채택을 성공으로 간주하지 않는다.

## 9. 단계와 승인 경계
| 단위 | 결과 | 선행조건/종료 |
|---|---|---|
| PREP01 현재 | 설계·평가 계획·다음 작업지시 | 문서 검토 후 보고/STOP |
| FIXTURE01 다음 제안 | 합성18사례·독립 정답표·기계 판독 계약 | 빌더 작성, 독립 리뷰, freeze 후 STOP |
| INSTALL01 | 고정 runtime와 우선 모델1개 설치·smoke | 정확한 manifest와 다운로드 범위 승인 후 실행; 기존 환경 보존 |
| EVAL01 | 쓰기 없는 후보 어댑터·A/B/C 평가 | 비교 모델 추가 다운로드 별도 승인 포함; 성능/안전 결과 후 선택 |
| VALIDATOR01 | 첫 좁은 행 참조 규칙 | 고정 oracle 음성시험·독립 리뷰; 기존 프로필 우회 금지 |
| UX01 | 후보·질문·검증·정확한 승인 연결 | 실제 전후 예시와 보류 흐름 확인 |
| FINAL01 | 회귀·실제 Excel·세 파일 수령 | 코드 확정 후 별도 최종 검증; 기존 미해결 gate 포함 |
